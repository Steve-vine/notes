Found in Sprint 46 Estate testing. On env-staging-uk, all 30 Argo Rollouts across the four chinwag namespaces (chinwag-dev/-test, chinwag-v2-dev/-test) sync correctly, but they have been merged down to just 3 visible entities. Searching "chinwag" therefore returns 3 workloads instead of ~30.

**Cause:** the Kubernetes connector emits a `datadog:service:<tag>` cross-key per workload (`connectors/kubernetes.py`). When many distinct workloads share the same DataDog service tag, they all resolve to the same cross-key and merge into one entity. Merges are never torn down (Sprint 45 semantics), so the collapse is permanent without a fix + data repair.

**Confirmed merge groups (env-staging-uk, all Rollouts):**
- "chinwag-task-scheduler" (dd tag chinwag-v2): 16 Rollouts from chinwag-v2-dev + chinwag-v2-test
- "chinwag-task-scheduler" (dd tag chinwag): 12 Rollouts from chinwag-dev + chinwag-test
- "chinwag-chat": 2 Rollouts (chinwag-dev + chinwag-test)
- "scout-ui": 2 Rollouts (scout-api + scout-ui in scout-test)

**Scale:** 95 synced workloads → 67 visible entities (28 hidden). All other types on this system are 1:1 (services, namespaces, hosts, other). Deployments/StatefulSets/DaemonSets unaffected here — only Rollouts carried the shared tag.

**Needs:** stop the shared-service-tag cross-key from merging distinct workloads (e.g. only materialise when 1:1, or scope it), plus a repair path for already-collapsed entities.
