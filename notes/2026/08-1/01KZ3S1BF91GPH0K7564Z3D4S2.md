    Root cause confirmed as described: reconcile_discovered resolved every discovered entity against its cross-keys with no cardinality guard, so the first workload to carry a shared datadog:service tag materialised the alias and every later carrier merged into it (discovery.py auto-merge is destructive and unrecorded, so the collapse was permanent).

    Fix, two parts:
    1. Prevention — a cross-key carried by more than one discovered entity in a batch is now treated as ambiguous: it identifies a group, not an identity (ADR 0073 §5 — an Application is several workloads). Ambiguous keys are excluded from resolution and never materialised, and a previously materialised harvested claim is torn down the moment its key stops being 1:1. Asserted aliases are untouched.

Repair — migration 0090 finds collapsed entities (≥2 scoped workload native keys + a datadog:service alias), keeps the oldest workload alias, frees the rest for re-discovery on the next sync, drops the shared service alias and clears harvested edges for a clean rebuild. Found in Sprint 46 Estate testing. On env-staging-uk, all 30 Argo Rollouts across the four chinwag namespaces (chinwag-dev/-test, chinwag-v2-dev/-test) sync correctly, but they have been merged down to just 3 visible entities. Searching "chinwag" therefore returns 3 workloads instead of ~30.

**Cause:** the Kubernetes connector emits a `datadog:service:<tag>` cross-key per workload (`connectors/kubernetes.py`). When many distinct workloads share the same DataDog service tag, they all resolve to the same cross-key and merge into one entity. Merges are never torn down (Sprint 45 semantics), so the collapse is permanent without a fix + data repair.

**Confirmed merge groups (env-staging-uk, all Rollouts):**
- "chinwag-task-scheduler" (dd tag chinwag-v2): 16 Rollouts from chinwag-v2-dev + chinwag-v2-test
- "chinwag-task-scheduler" (dd tag chinwag): 12 Rollouts from chinwag-dev + chinwag-test
- "chinwag-chat": 2 Rollouts (chinwag-dev + chinwag-test)
- "scout-ui": 2 Rollouts (scout-api + scout-ui in scout-test)

**Scale:** 95 synced workloads → 67 visible entities (28 hidden). All other types on this system are 1:1 (services, namespaces, hosts, other). Deployments/StatefulSets/DaemonSets unaffected here — only Rollouts carried the shared tag.

**Needs:** stop the shared-service-tag cross-key from merging distinct workloads (e.g. only materialise when 1:1, or scope it), plus a repair path for already-collapsed entities.
