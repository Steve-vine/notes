Found during ISE Test Plan execution (2026-08-06): blocks inserted into the incident history via MCP `record_note` show raw markdown — e.g. `**Azure VM health sweep (CSP Softcat, all 12 VMs in uksouth):**` renders with literal asterisks.

Cause: `MessageContent` (`app/frontend/src/components/chat.tsx` ~line 50) deliberately renders **user-role** turns as plain pre-wrap text and only assistant turns through `<Markdown>` (the ISE-70 decision: "the operator's text verbatim"). MCP `record_note` writes notes as a `user` turn in the incident conversation (ADR 0024), so Claude-authored notes — which are naturally markdown-formatted — hit the verbatim path. The timeline (`pages/issue/IssueTimeline.tsx` → `MessageEventItem` → `MessageContent`) and issue chat share this component.

Task (Steve-decided): render **all** text blocks in the incident log as markdown — user turns included — superseding the ISE-70 verbatim rule for display. Notes:
- Hand-typed operator text is markdown-benign in the common case, but check that plain text with incidental `*`/`_`/`#` doesn't mangle (react-markdown handles most of this gracefully); keep whitespace behaviour sane for single-line notes.
- Applies wherever `MessageContent` renders (incident timeline + issue chat) so the two surfaces stay consistent.
- Check other timeline text blocks (audit/detail strings) for the same gap while in there.
- Verify against the real incident from today's test session (the Azure VM health sweep note).
