    Deliverables:
    - `docs/decisions/0094-integration-packs.md` (ADR 0094, Accepted)
    - `docs/briefs/integration-packs.md` — the v1 authoring spec a third party writes packs against
    - connectors brief gains a "Connector, or pack?" section; both READMEs indexed

    The four decisions the ADR turns on:

    1. **No executable content, at all.** No expressions, templates, scripts, author-supplied regexes or arithmetic — every field is a literal, a closed-menu choice, or a path selector. This is precisely why the auth and pagination menus are closed rather than having a "custom" escape hatch: an escape hatch is a scripting language wearing a hat, and it would move the safety argument from structural to review-based overnight. A source that doesn't fit gets a menu entry added to core through CI (a bad day for one integration, a good decade for the platform), or it gets a connector.

    2. **No actions, ever** — not "not yet". `action_catalogue()` returns empty unconditionally, `credential_use().write` is False, and there is no pack field that could populate a catalogue. Accepting an author-written risk tier wouldn't weaken ADR 0017's tiered model, it would end it: "T1" would from then on mean "someone said T1". `observations` is excluded too, for a quieter reason — an Observation carries ISE's own confidence, and a pack has no judgement of its own to express, it only forwards what the source states.

    3. **Rung-1 vocabulary only.** Entity types, edge types and severities map onto the canonical lists (ADR 0086); an unmappable value is an install-time error rather than a sync-time surprise. A pack-minted type would render as a blank chip nothing could filter on and would fragment the estate along a boundary no screen expresses — `other` is the honest answer.

    4. **Runtime artefacts, never a migration.** Stored in the DB, `connector_type` namespaced `pack:<key>` so a pack can't shadow or override a built-in Type.

    Two costs recorded up front rather than left to be discovered: `get_connector` has ~40 call sites with no session, so pack resolution is a process-local cache with a ~30s TTL — an installed pack goes live across API + worker within about half a minute, not instantly. And a wrong pack produces *wrong* entities rather than none, unreviewed by anyone; that is the price of the release cadence, mitigated by install-time validation and the `source_of_record` fail-closed default.

    Scoped out to Packs II deliberately: the `evidence:` section is reserved and v1 rejects it with a pointer, rather than shipping a declared-but-unfetchable capability — ADR 0031 §2 made capability the thing the UI degrades by, so advertising Evidence that returns nothing would put a broken promise on the System detail page and in the agent's tool list.

    The brief is written to be implementable and testable as-is: ISE-502/503/504 build exactly what it documents.

The ADR that takes the step ADR 0027 §6 deferred, scoped to read-only declarative packs (the 0031 lineage): a versioned YAML document declaring HTTP client (auth from a fixed menu), pagination (fixed menu — the four idioms already in the connector package), endpoints, and JSONPath mappings to entities/alerts/evidence. Capabilities capped at entities + alerts + evidence; **no actions, ever** (ADR 0017 review is the safety mechanism). Entity types are rung-1 only (existing canonical types or `other` — kind-dictionary doctrine); no migrations from packs. Deliverables: `decisions/00NN-integration-packs.md` + the pack schema spec (`docs/briefs/integration-packs.md`) that a third party authors against.
