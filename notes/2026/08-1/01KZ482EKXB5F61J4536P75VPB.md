    Done in PR #443 (feature/ise-519-graph-spacing). A Spacing slider now sits beside Depth, 0.5× to 3×, default 1× (marks: Tight / 1× / Wide).

    Two things I want to flag, because they're where this could have quietly failed:

    **It had to reach every layout mode, not just the rings.** Blast mode scales its ring gap, elk scales node and inter-layer spacing for flow/containment, and d3's explore mode scales charge, link distance and collide radius together — that last bit matters because a longer link against unchanged repulsion just settles back to where it started. A slider that visibly did nothing in two of the four modes would have read as broken.

    **Spacing had to join the layout signature.** The canvas warm-starts from the existing frame (ISE-242) so a depth or filter change doesn't make the camera jump. That same machinery would have kept every node exactly where it was on a spacing change, and the slider would have appeared completely dead. Including spacing in the signature makes it a from-scratch re-lay.

    Persisted like depth, and deliberately not a filter — "Clear filters" shouldn't reset how you like to read a graph. Nodes you've dragged keep their positions, since a drag is an explicit placement; Reset layout still clears those. Tell me if you'd rather a spacing change overrode drags too.

    Tests: ring-radius doubling, clamp behaviour at both extremes, and the control rendering on the Explorer. Full suite green (551), build/eslint/prettier clean. The ranges and the feel are visual, so worth your eye on staging.

    Note: this was the only task in ToDo — there wasn't a second one to pick up alongside it.
