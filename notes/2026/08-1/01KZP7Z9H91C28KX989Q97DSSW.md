Found 2026-08-10. `get_state_slices` and `get_slice_payload` are the AI's primary "what is the state of this thing" tools, in the shared `DIAGNOSIS_TOOLS` set every incident agent carries. For most of the estate they have nothing to return.

`read_state` is opt-in — `connectors/base.py:1049`, "Default empty — a connector with no state/evidence slices need not implement it" — and **three** connectors implement it: datadog, kubernetes, m365.

Enabled systems with **zero** state snapshots, ever (staging, 2026-08-10): `AWS Production`, `AWS Staging`, `CSP Softcat` (azure), `Cloudflare`, `Confluence`, `EntraID`, `FreshService`, `Moneypenny-Development` (github), `Microsoft Teams`, `Local` (servers), `Status Pages`, `ISE Estate` (webhook) — **12 of 14**.

**Why it bites.** On the mpwxscript incident the agent called `get_state_slices` twice and `get_slice_payload` twice, then wrote: *"get_state_slices and list_system_issues returned no data at all; get_slice_payload found no snapshot for either 'servers' or 'Local'."* That is presented as an absence of estate knowledge. It is an absence of a connector method. The estate knew a great deal about that host — aliases, register entry, reachability — none of it in a state slice.

This is the same failure as [ISE-635] and [ISE-633]: an emptiness that belongs to ISE's own configuration, narrated as a fact about the world. Here it is worse than in the UI, because the agent's answer *is* the product surface — an operator reads "no data at all" and concludes ISE knows nothing about the machine.

**The question to settle first**: is the gap that these connectors *should* publish state slices, or that the tool should say "this system publishes no state slices" rather than returning empty? They are different fixes and probably both true — the servers connector in particular has a register, coverage and facts that are exactly state-slice-shaped, while Teams or Confluence plausibly have nothing to publish and should say so.

**Scope**
- The tool distinguishes "this system publishes no state slices" from "this system published none yet" from "it published some and none match" — the caller can only act on the third.
- Decide per connector whether state slices should exist. Servers is the strongest candidate (it is what a diagnosis about a host wants), then AWS/Azure/EntraID.
- Where a system publishes no slices, the agent's answer should route to what *is* available for it — entities, findings, evidence queries — rather than reporting a blank.

**Acceptance**: an agent asked about a host on a system with no state slices says so and reaches for what that system does offer; no incident summary claims "no data at all" about an entity ISE holds a register entry for.
