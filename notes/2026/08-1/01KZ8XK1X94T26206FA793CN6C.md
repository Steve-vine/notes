Found during Sprint 50 incident-management testing: asked the incident chat what synthetic test a failing Datadog Synthetics monitor performs and what the failure result is — it couldn't answer. Confirmed this is an ISE capability gap, not an API limit: the Datadog connector (`connectors/datadog.py`) has no synthetics support; only monitor alert metadata is synced.

## What the Datadog API offers — CONFIRMED against docs.datadoghq.com 2026-08-05

- `GET /api/v1/synthetics/tests/{public_id}` — full test definition: request/steps, assertions, locations, schedule (API-test and browser-test variants exist; browser via v2).
- `GET /api/v1/synthetics/tests/{public_id}/results` and `/results/{result_id}` — per-run results: pass/fail, the failed assertion, HTTP status code, response time, per probe location.
- Requires `synthetics_read` permission on the API/app key (verify the current key has it).

## Scope

- Sync (or fetch on demand as an evidence tool, like `query_metrics`/`search_logs`) the synthetics test behind a monitor, and its recent failing results, so incident chat / diagnosis can state what the test does and the exact assertion that failed.
- Link from a synthetics-monitor finding to its test via the monitor's synthetics test id/public_id.
- Surface in the UI on the incident where the alert's monitor is a synthetics check.
