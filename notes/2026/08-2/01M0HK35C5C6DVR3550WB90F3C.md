COM-324's `provision_mapped_users` logs `extra={"created": ...}` — `created` is a reserved `LogRecord` attribute, so stdlib logging raises `KeyError` the moment provisioning creates ≥1 user. The pass rolls back (users never commit), the non-GraphError crash never records a failure on the status row, and the overlap guard then skips the next two ticks. Seen on staging 2026-08-21: every third pass crashes, S.Vine never appears in Users, recert schedule still shows "Not Compass users". Tests passed because pytest's WARNING log level short-circuits `logger.info` before `makeRecord`.

Fix: rename the extra key; record unexpected exceptions on the status row (then re-raise) so a crash can't strand the overlap claim; regression test runs provisioning with INFO logging enabled.
