Send as a real mailbox in the tenant. The cheapest credential story of the four — `core/graph.py` already speaks client-credentials Graph (sync httpx, explicit timeouts); this mostly needs `Mail.Send` and `POST /v1.0/users/{mailbox}/sendMail` (returns no body).

Stacks on [COM-230].

## Its own app registration — deliberately NOT `m365_settings`

Compass already holds an Entra app registration for managed content (`models/m365_settings.py`, DEV-772/ADR 0034). **Do not add `Mail.Send` to it.** The ISE-745 lesson: consent and revocation must be independent — sharing one registration means revoking one capability revokes both, and the managed-content consent screen would silently be asking for the power to send mail as anybody in the tenant. The transport carries its own tenant id + client id + client secret in its credential blob; `m365_settings` and `get_m365_config` are untouched.

## Scope

- Credential: tenant id + client id + client secret. Reuse `core/graph.py`'s token-acquisition shape (`_get_token`, `core/graph.py:116`) against the transport's own credential — don't grow a second Graph client dialect.
- **The mailbox IS the from address — one field, not two.** Graph sends through `/users/{mailbox}/sendMail` and the message arrives *from* that mailbox; a separate mailbox field only lets the two disagree, which Graph answers with `ErrorSendAsDenied` — a setup failure manufactured by the form. The transport's `from_email` (the shared identity from [COM-230]) is the mailbox.
- **`save_to_sent_items` always true, no toggle.** The sent copy is the record that Compass sent something, in a mailbox an operator already has open; a defaulted-but-invisible setting is one nobody knows exists. Remove the choice rather than add a control.
- `health_check` acquires a token **and resolves the mailbox** (`GET /v1.0/users/{mailbox}`). Token-only is not enough — a plausible-but-wrong mailbox 404s exactly like a permissions error, and that ambiguity costs a live setup session. On a 404, name which of the two it is.

## Two things the credential form's guidance must say out loud

1. **The `Mail.Send` application permission lets Compass send as *any* mailbox in the tenant** unless scoped by an Exchange ApplicationAccessPolicy. Real blast radius, invisible unless the guidance says it — put it where the admin reads while granting consent, and **assert the warning text with a test** so a later prose tidy-up fails the build instead of quietly dropping it (ISE-745 did exactly this).
2. **Graph's simple sendMail caps attachments at ~3MB.** Above that needs an upload session — out of scope. This is the number `core/mail.py`'s global attachment cap is built on ([COM-230]).

## Honest limitation — state it in the module docstring

`sendMail` takes one body with one content type: the HTML part is sent and the plain-text alternative is not carried (SMTP and SendGrid send both). Exchange Online generates its own fallback. Worth knowing if a pager gateway is ever subscribed through this transport.
