Reports (ADR 0095) shipped a calendar cadence, a rendered PDF and an artifact store — and no way for the result to reach a person. A weekly report is currently seen only by whoever remembers to go and look, which is indistinguishable from the feature not running.

Stacks on [ISE-743].

## Scope

- **Migration — next free** (the sprint's migrations stack in one chain behind [ISE-743]; re-check `origin/main`). `Report` gains `email_enabled` (bool) and `recipients` (JSONB list, validated at the API boundary and capped). Edited in `components/reports/ReportModal.tsx` alongside the schedule, since "when it runs" and "who gets it" are one thought.
- `ReportRun` records `email_status` / `email_error`, shown in `ReportRunsCard.tsx`. **A report that rendered but reached nobody must not look identical to one that arrived** — that is the whole failure mode being closed here.
- Sending happens after a successful run, through the `ISE_api/mail` service — the report code never names a transport.

## Two decisions

**Scheduled runs email; "Run now" does not.** A manual run is already being watched by the person who pressed it, and mailing them a copy of what is on their screen is noise.

**The size rule.** Attach the PDF when it is under the cap (~3MB — the tightest transport's limit, set by Graph's simple sendMail, see [ISE-745]). Over the cap, send a link to the run in the app **and say why it is a link rather than an attachment**. Silently dropping the attachment and failing the whole send are both worse: one is invisible, the other loses the report over a detail nobody chose.

`none_as_null=True` on any nullable JSONB added here — a Python `None` otherwise persists as JSON `null`, which is not SQL NULL, and every `IS NOT NULL` predicate then matches every unset row. That trap is already in this exact model: `Report.schedule` carries the comment.
