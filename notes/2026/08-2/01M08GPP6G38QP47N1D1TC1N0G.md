The safety net behind the expedited path (2026-08-17 amendment). During a live incident an engineer often won't open Compass at all — they'll create the user or group directly in Entra. The expedited mode (COM-239) only covers engineers who were already being diligent; **detection covers everyone else**, and the recert campaigns remain the periodic backstop behind both.

* **Diff at sync**: each directory-mirror sync pass (COM-237) compares what changed in the tenant against what Compass executed (the per-subject result rows from COM-239). New users, new groups, and membership changes to **managed** (matrix-mapped) groups with no corresponding executed request become **unrequested-change items**.
* **Same validation queue**: items land in the `pending_validation` queue beside expedited changes (COM-240) — one place a validator works, one mental model. Per item: **adopt** (attach intent retrospectively — who/why, optionally amend first via a linked corrective request through the standard write path, then validate) or **flag for reversal** (raising a corrective request through the normal maker-checker path — reversal is itself a directory write and gets a second person).
* **Scope guard**: membership detection covers managed groups only — diffing every unmanaged group in the tenant would drown the queue; unmanaged-group noise stays out by design (the matrix defines what Compass governs). New users and new groups are always detected — creation is exactly the incident-time act this exists for.
* **Idempotent + audit-quiet**: detection runs on the worker (actorless — no activity-log noise from the scan itself); items dedupe on (object id, change, observed sync window) so a re-run creates nothing new (ADR 0006). The items themselves are governance entities: audited, SLA'd, nagged via the reminders engine like expedited validations.
* Surfacing: count on the Access dashboard tile with the validation queue; a persistent stream of unrequested changes is itself a finding worth seeing.

Refs: ADR 0045 (expedited/validation model), 0006, 0023; COM-237 (mirror diff point), COM-239 (executed-change ledger to diff against), COM-240 (queue UI).
