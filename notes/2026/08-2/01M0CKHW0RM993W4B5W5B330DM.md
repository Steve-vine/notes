Add full column sorting to both directory inventory lists (COM-253 View Groups, COM-255 View Users): click a header to sort ascending, click again for descending, with the usual direction indicator.

* **Server-side**: `order_by` + `direction` params on both list endpoints (COM-252/254) — sorting composes with the existing filters and pagination, so page 2 of a sort is real, not a client-side shuffle of the fetched page. Whitelist the sortable columns server-side (exactly the visible ones); reject anything else.
  * Groups: Name, Group type, Membership type, Email, Source, Members count (the COM-270 aggregate — sorting by it sorts the aggregate in SQL).
  * Users: Display name, Enabled, User Type, User principal name.
* **Stable ordering**: always append a deterministic tiebreaker (object id) so equal values don't jitter across pages or refetches.
* **Case-insensitive** text ordering (name/UPN/email) — mixed-case directory data sorts by spelling, not by ASCII accident.
* **UI**: shared sortable-header treatment across both tables (they already share scaffolding per COM-255) — indicator on the active column, keyboard-accessible headers; default sort stays Name ascending. Persist the choice alongside the existing persisted filters if that pattern is already wired; don't build persistence just for this.

Refs: COM-252/254 (endpoints), COM-253/255 (tables), COM-270 (members-count sort lands together with this if both are open).
