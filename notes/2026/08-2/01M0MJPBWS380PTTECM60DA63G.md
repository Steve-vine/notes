The third surface, and the first **external** one: the supplier's own people (vendor contacts, not Compass users) complete assessments here. Everything reachable is scoped to one vendor by a capability token — there are no accounts, no sessions, no roles.

## Access model (decided 2026-08-22)

- [ ] **One portal destination per vendor; per-contact tokens.** Each compliance contact holds their own token to the same vendor portal, so answers and submissions are attributable to a named contact and one contact's link can be revoked alone.
- [ ] Token table: (vendor_id, contact_id, token **hashed at rest**, created/expires/revoked). Tokens are (re)generated by the Start flow for the ticked contacts — regeneration revokes that contact's prior token — and all of a vendor's tokens are revoked when its last open assessment closes.
- [ ] Token validity is bounded by the latest `valid_until` across the vendor's open assessments.

## Separate ingress

- [ ] Its own hostname/ingress in the Helm chart, distinct from the main app (ADR 0008 pattern) — the supplier never touches the employee ingress; the main app never serves token routes. Document the boundary in the ADR this feature gets.
- [ ] A dedicated API namespace (e.g. `/api/vendor-portal/…`) authenticated **only** by token — deliberately outside `require_*` user guards; the token resolves to (vendor, contact) and that pair is the whole authorization. Rate-limit / brute-force posture worth a line in the ADR (tokens are high-entropy, hashed, revocable).

## The supplier's UI

- [ ] Landing: the vendor's open assessments, each with progress and its expiry date; closed/completed ones are not shown (this is a workbench, not a record — the record lives internally).
- [ ] Completing: question-by-question form with incremental save (the lifecycle task's upsert API), progress indicator, and final submit once required questions are answered.
- [ ] Expired/revoked token and no-open-assessments states: polite dead ends that leak nothing (no vendor name on a bad token).

- [ ] Tests: token auth (bad/expired/revoked 401, no enumeration); vendor scoping (token A cannot touch vendor B); attribution recorded per contact; incremental save + submit round-trip; ingress config verified in chart tests/smoke.

An ADR is required: first external surface, new authn model, new ingress.
