The sprint's role-model decision made concrete: Entra group membership drives Compass roles, but the mapping is **Compass-owned and audited** — e.g. `compass-vendor` → vendor_manager + vendor_owner. Role *policy* changes stay in Compass's activity log; day-to-day *assignment* happens in Entra.

* **Model**: `sso_group_role_mappings` — Entra group (object id + display name captured at creation), → one-or-many Compass `Role` values; unique per group; joins `_AUDITED_TABLES` (a mapping edit is a privilege-policy change — exactly what an auditor asks about). Global, not company-scoped (app roles are global, ADR 0026).
* **Resolution**: effective roles for an `auth_provider="entra"` user = **union of mapped roles across their SCIM-synced groups**. Users whose groups map to nothing hold no roles and surface visibly as "no mapped roles" (decided in the ADR — no silent viewer default). Manual role editing is disabled for Entra users (derived-only; the Users section explains why and links the mappings panel); local accounts keep manual roles.
* **Recompute triggers**: SCIM group-membership PATCH (primary), plus a defensive refresh at SSO sign-in so a missed webhook can't leave stale privilege. Role changes recompute-and-persist (not computed per-request) so the Users list, activity log and recert-style reviews all see concrete values.
* **Admin UI**: a Mappings panel (Admin ▸ Users or ▸ Integrations — decide with the frontend task): group picker fed from the synced SCIM groups (or free-entry object id before first sync), multi-select of Compass roles, affected-user count per mapping, warning state when a mapped group no longer syncs.
* **Guard rail**: mappings that grant `admin` (or the ADR 0045 access roles) deserve friction — at minimum a confirmation naming the blast radius; consider requiring a second admin (the maker-checker instinct applied to privilege policy). Decide in the ADR, implement here.

Refs: ADR 0046, 0026, 0023, 0045 (role-vocabulary discipline); COM-249 (SCIM groups feed).
