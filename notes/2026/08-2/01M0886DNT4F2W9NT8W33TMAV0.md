The operational face of JML in the new Access section.

* **Raise**: per-kind forms — joiner (batch entry: add rows or paste a list; business role picker per subject), mover (directory-user picker from the mirror, current vs proposed role with a live membership diff preview), leaver (user picker, shows what will be disabled/removed before submission).
* **Approve**: a queue of `pending_approval` requests with the full diff of what execution will do; approve/reject with comment; the UI never offers approve to the requester (server enforces, UI shouldn't tease).
* **Execute + results**: progress per subject; the joiner **one-time password list** displayed exactly once behind an explicit reveal (copy-all affordance for batches, "this will not be shown again" — mirrors the API's view-once contract); per-subject failures shown with the Graph error and a retry affordance for the failed subset.
* **History**: request list with status pills (`StatusPill`), filterable by kind/status; request detail shows the request → approval → execution timeline.

House patterns: TanStack Query hooks per resource, Mantine forms, toasts via the central `MutationCache`, skeletons + friendly empty states (ADR 0022). Refs: ADR 0045, 0017; `vendors/` feature folder as the structural model.
