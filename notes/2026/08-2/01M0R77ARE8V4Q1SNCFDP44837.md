Closing the loop on COM-397's lesson: three defects in the actor-enrichment path all came from assumptions about the tenant that were never checked *against* the tenant, and the unit tests stayed green throughout because they encoded the same assumptions.

One such assumption is still live and untested. `_AUDIT_ACTIVITIES` in `tasks/directory_sync.py` maps each item kind to the `activityDisplayName` values that mean it:

```
user_created   -> {"Add user"}
group_created  -> {"Add group"}
group_deleted  -> {"Delete group"}
member_added   -> {"Add member to group"}
member_removed -> {"Remove member from group"}
```

Those came from documentation, not from this tenant. If a real change surfaces under a name not in the map — an on-prem-synced variant, a differently-named activity, or one Microsoft renames — the item **silently never attributes** and sits as "not found yet" until it ages out to `unknown`. Exactly the shape of the bug Steve reported, and it would look identical from the UI.

- [ ] Pull the distinct `activityDisplayName` values the tenant actually emits against user and group target resources over the audit retention window, and diff them against the map.
- [ ] Add anything real that is missing; record anything deliberately excluded and why.
- [ ] Consider **logging** an unmatched-but-plausible entry (right object, right window, name not in the map) rather than discarding it silently — that turns the next occurrence into a log line instead of an invisible gap.

The technique is the one that worked for the group reconciliation on 2026-08-23: ask the tenant rather than reason about it. Read-only, an hour or so, and it either confirms the map or finds the next COM-396.
