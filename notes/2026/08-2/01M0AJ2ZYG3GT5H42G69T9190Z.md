New **View Users** entry in the Access section nav, directly below View Groups — same format and interaction model as COM-253, over the COM-254 API.

* **List**: paginated table — **Display name, Enabled, User Type, User principal name** — filter bar matching View Groups: debounced free-text on display name, selects for Enabled (enabled/disabled) and User Type (Member/Guest). Enabled as a status pill (disabled accounts visually muted — a leaver disabled via JML should read as such at a glance).
* **Detail modal** (click a row): identity header (display name, UPN, enabled state), then **Object ID** (copy affordance), **Created on**, and the assignment panels — **Active assignments** and **Eligible assignments** (PIM directory roles; privileged roles carry the COM-253 shield badge so a Global Admin stands out here exactly as a role-granting group does), **Groups** (direct memberships, linking through to the View Groups modal where the group is in the inventory), **Applications** (enterprise-app assignments), **Licenses** (friendly SKU names). The modal loads panels independently (the detail endpoint aggregates several sources — skeleton per panel, and the backend's degraded states render as explicit notices, e.g. "eligible assignments unavailable" — never silently empty).
* **Azure Portal link**: "Open in Azure Portal" on row overflow + modal header — `https://portal.azure.com/#view/Microsoft_AAD_UsersAndTenants/UserProfileMenuBlade/~/overview/userId/{objectId}` — new tab, external-link affordance.
* Gated `RequireSection section="access"` / `require_access_read`; read-only, no write affordances — JML remains the only way accounts change. Remember the `App.tsx` placeholder-exclusion list.

**Deferred (2026-08-18, Steve): the Azure role assignments panel** — parked as the COM-256 candidate; the modal's panel layout should accommodate it later without redesign.

Refs: ADR 0045, 0022, 0017; COM-254 (API), COM-253 (the format twin — share the table/filter/modal scaffolding where it doesn't contort).
