The second transport, and the one with the widest reach: a generic SMTP relay covers an on-prem Exchange, a smarthost, Mailgun, SES-over-SMTP — anything that speaks the protocol.

Stacks on [ISE-743].

## Scope

`connectors/smtp.py` over stdlib `smtplib`. Credential/config fields: host, port, security (`none` / STARTTLS / implicit TLS), username, password (secret). `health_check` connects, negotiates the chosen security, authenticates and quits — so a wrong port or a refused login is visible on the tile rather than at first send.

## The gotcha this task exists to get right

**ADR 0092 bounds outbound HTTP in one place. SMTP is not HTTP.** `smtplib` goes nowhere near `http_bounds`, and its default timeout is the global socket default — i.e. *wait forever*, which is precisely the behaviour that turned the 2026-08-06 DNS outage into a ~10,000-task broker backlog (ADR 0091/0092).

So this connector sets its **own connect and command deadlines explicitly, with a comment saying why** — an unbounded send from a worker is the same failure in a new place, and the next reader will otherwise assume the platform already covered it.

Mirror ADR 0092's reasoning for the numbers: short connect (a TCP connection not made in ~5s will not be), generous command deadline, no library-level retry (the delivery sweep is already the retry).
