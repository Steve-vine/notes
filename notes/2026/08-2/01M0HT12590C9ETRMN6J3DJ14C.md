Stacked trains are currently driven by hand: merge parent → rebase child onto main → retarget → wait for CI → repeat, and two sessions doing it concurrently collide on main. Evaluate GitHub's merge queue: PRs enter the queue when green, GitHub builds the speculative merge, and the train advances itself. Touches the ADR 0041 trigger model (merge_group event needs the full suite) and branch protection — write up as an ADR amendment if adopted.
