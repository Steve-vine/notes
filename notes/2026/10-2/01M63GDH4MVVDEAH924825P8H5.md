Sprint 99, Browser Testing (ADR 0135, COM-1446).

## What people see

On staging, a company called **E2E Test Company** appears in the company switcher. Admin ▸ Integrations shows it has **no connections**: no Microsoft 365 / Entra, Active Directory, cloud or scanner.

A set of sign-ins, all named "E2E …":
- **E2E Admin A** and **E2E Admin B**: administrators, so one can raise something and the other approve it;
- **E2E Analyst**, **E2E Assessor** and **E2E Viewer**;
- **E2E Vendor Admin** and **E2E Access Manager**;
- **E2E Vendor Contact**: a compliance contact on a test vendor in the test company, who signs in to the vendor portal;
- **E2E Asset Owner** and **E2E Attester**: user-portal accounts.

Each internal account's last company is set to E2E Test Company, so it opens there.

## Notes (technical)

- `scripts/e2e/provision-staging.py`, idempotent, driven through the public API with an admin API token that Steve creates (ADR 0007). It creates or updates the company, the accounts and their roles, and the test vendor with its contact.
- It **refuses to continue** if the test company has any connection: directory, AWS, Azure, GCP or discovery.
- Passwords are generated once and kept in `~/.config/compass-e2e/staging.env` (mode 0600), never in the repo or in a Notuvia comment. The same values go to GitHub Actions as `staging` environment secrets (`gh secret set --env staging`).
- Email addresses must pass the app's validation (reserved test domains such as `.invalid` may be rejected). Mail goes to the mail catcher whatever the domain.
- If an account or grant can't be made through the public API, that's a missing API: the task joins the chain.

**Chain:** independent (a script and secrets; no migration or API change).

**Done when:**
- on staging, every account signs in and lands where it should (portal accounts on their portal);
- the test company shows no connections;
- re-running the script changes nothing.
