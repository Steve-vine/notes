Sprint 99, Browser Testing (ADR 0135, COM-1446). Needs the test accounts (COM-1447).

## What it gives

In a Claude Code session on g5, Claude can:
- open staging and sign in as any test account;
- use the screens as a person would: click, type, choose, upload;
- take screenshots and look at them;
- read the emails Compass sent, in the staging mail catcher. For example, a vendor's questionnaire link or a password reset.

This is used for exploratory checks and for the pre-UAT pass on each sprint. It runs headless, so Steve doesn't need to be at the machine. The browser can only open the staging sites:
- compass.citops.net;
- vendor-portal.citops.net;
- trust.citops.net.

## Notes (technical)

- The Playwright MCP server (`@playwright/mcp`, pinned to an exact version) goes in the project's `.mcp.json`.
- Run it headless with an isolated profile and `--allowed-origins` set to the three staging hosts. It uses the Chromium already on g5 (`~/.cache/ms-playwright`).
- **Passwords never pass through the conversation.** A sign-in helper (`scripts/e2e/sign-in`) reads `~/.config/compass-e2e/staging.env`, signs in, and saves a signed-in session per account under `~/.config/compass-e2e/state/`. The browser loads the session for the account being used.
- The mail catcher (mailpit, in-cluster) is read through its API, via a port-forward or an internal-only route. Not a public ingress.
- Screenshots go to the session scratchpad.
- Write a short how-to in `scripts/e2e/README.md`, covering switching accounts, reading mail and what not to do: never production, never a company other than E2E Test Company.

**Chain:** independent (tooling and config only).

**Done when:**
- in a session, Claude signs in as E2E Admin A and as E2E Viewer and shows a screenshot of each one's home screen;
- Claude reads a password-reset email for a test account from the mail catcher;
- opening any non-staging site is refused.
