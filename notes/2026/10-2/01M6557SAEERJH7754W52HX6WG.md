    **What it was:** not a leak. The API handles requests on up to 40 threads, and Linux's memory allocator gives threads their own memory pools (up to 8 per CPU; g5 has 16). Memory freed after a request stayed spread across those pools rather than being reused, so the API grew with every walk and never gave it back. Nothing in Compass's code holds on to responses: its caches all take no arguments.

    **Measured on staging** (the API's memory, three walks through every screen for 7 accounts, fresh restart each time):

    | | start | walk 1 | walk 2 | walk 3 |
    |---|---|---|---|---|
    | as it was | 519 MB | 713 | 771 | 825, rising ~55 MB a walk |
    | two pools (`MALLOC_ARENA_MAX=2`) | 512 MB | 626 | 632 | 617, flat |

    The walks took 4.3 min either way, so there's no speed cost.

    **Fix:** the setting goes in the backend image, so it applies wherever Compass runs, production included.

    For the experiment I set it directly on the staging API (`kubectl set env`). I'll remove that once the image carries it, and confirm the deployed image has it.

Defect found by the browser suite (COM-1449), sprint 99, on staging 2026-10-30.

## What happened

- 00:49 GMT: staging's API was OOM-killed at its 1 GB limit. It had been up 40 minutes, during which the suite walked every screen for every test account about eight times.
- Measured after the restart, one browser walking every screen and tab for 7 accounts:
  - first walk: 555 → 714 MB (+160);
  - second walk: 714 → 819 MB (+105).
- It keeps rising, more slowly each time. Production has the same 1 GB limit per API copy.
- Each staging deploy restarts the API, which hides this. A long-lived production API would meet it through ordinary use, more slowly.

## To find out

Whether this is a leak (something holding on to every response) or caches settling at a size above the limit. Profile the API across repeated walks (tracemalloc snapshots, or memray on a local run of the suite). Either fix what holds the memory, or size the limit to the plateau with headroom.

**Chain:** independent unless the fix touches the API's behaviour.

**Done when:** three walks in a row leave the API's memory flat, or a measured plateau sits well inside the limit.
