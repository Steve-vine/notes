Sprint 93, Vulnerabilities - Cloud sources (where it was seen this time; the problem is app-wide). Found by Steve on staging, 2026-10-28, while testing sprints 90–93. **Steve has hit this several times.**

## What's wrong

Integrations ▸ AWS ▸ Status showed "The user may not read Security Hub (securityhub:DescribeHub) — update the user's policy from the current template (every region)" in dark red. On a dark background it is close to invisible.

The cause: these messages ask for a **fixed dark shade** (`red.7`, `red.8`), which is the same colour in light and dark mode. Mantine's plain `c="red"` (and `--mantine-color-red-text`) switches to a lighter red in dark mode; a fixed shade doesn't. The app's dark primary shade is 4 (`theme.ts`); anything 7+ is too dark on a dark background.

Today on main:
- **`red.7` as text — 8 places:** `integrations/CloudAccountsStatus.tsx` (account error, read problems), `ActiveDirectoryStatus.tsx` (×2), `MicrosoftStatus.tsx`, `StorageStatus.tsx`, `vulnerabilities/VulnerabilitySummaryCard.tsx` (critical and overdue figures on the Dashboard).
- **`red.8`:** `ContentDetailPage.tsx` (an inline style) and the Critical severity colour in `vulnerabilities/labels.ts` (pills and charts).
- **The same problem in warnings:** `orange.8` as text in 12 places, plus `green.8` and `teal.7` once each.

## What people should see

- Every error message in dark mode is a red that reads clearly on the dark background, at least WCAG AA contrast (4.5:1 for body text). Warnings in orange, and the odd green or teal, likewise.
- Light mode looks as it does now.
- Severity pills and charts keep one scale (COM-1371) that still tells Critical from High in both modes.

## How

- Error text uses one colour that adapts to the mode: Mantine's `c="red"`, or a named token in `theme.ts` (e.g. `errorText`) set per mode. The same goes for warning text.
- Every fixed dark shade listed above is replaced.
- **A guard test**, like the screen-conventions test: it fails when a component's text colour is a fixed shade of 7 or above (`c="red.7"`, `'orange.8'`, `var(--mantine-color-red-8)` used as text colour), unless it's marked with a reason. That's what stops this coming back.
- A rule in `brief/information-architecture.md` → *Screen conventions*: error and warning text uses the adaptive colour, never a fixed shade.
- Check in a real browser in dark mode, not only jsdom: the Integrations Status tabs (AWS, Azure, Google Cloud, Microsoft, Active Directory, Storage), the Dashboard's Vulnerabilities card, a content page, and the Vulnerabilities register's severity pills.
