Sprint 100, Actions (ADR 0137 rule 6).

## What people see

- Today's single **Type** column mixes four kinds of label:
  - a state: "Plan overdue", "Unrequested change";
  - a call to action: "Vulnerability to fix", "Report to triage";
  - an event: "Risk tier rose";
  - a bare thing: "Gap", "Treatment".
- After this, the list has two columns:
  - **Type** is the thing: Gap, Risk, Treatment, Incident, Vulnerability, DDQ, Contract review, Audit request, Access request, Vendor, Asset, Policy, Plan activity, Data subject request, Document to sign…
  - **Action** is what to do: Remediate, Create a treatment plan, Review, Triage, Decide notifications, Fix, Answer questions, Approve, Validate, Sign, Renew…
- Incidents are **Incident**, never "Report".
- The filter chips work on **Type** (built in COM-1475, the screen task).
- **Polaris** gives the same Type and Action, so its answers stop calling DDQ questions and vulnerability fixes "Other / Other".
- The **actions email** groups by Type and leads each line with the Action.

## Notes (technical)

- Each source declares `subject_type` and `action` (labels shared by backend and frontend). `ActionOut` gains both, and the current `type` key stays as the internal identity (the digest's ledger is keyed on it, ADR 0055: don't break it).
- Frontend `action.ts`: the type map becomes Type/Action, plus `ActionsTable` columns. Portal page too.
- MCP `overview_list_actions`: replace the `kind`/`from` fields, and make the `kind` filter enum every Type.
- The exact wording for every type comes from COM-1468's per-type table.
