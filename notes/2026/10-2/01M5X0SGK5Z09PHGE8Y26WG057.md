## What Steve saw

1. After double-clicking the drag bar to minimise or restore the window, it could no longer be resized by dragging.
2. From then on the window wouldn't display properly, even after closing and reopening the browser. It had **no drag bar** and showed **just one line of text from the chat**.

## Cause

- **Minimised, the window is only the bar's height (18px).** Its content has `overflow: hidden`.
- **Hidden overflow can still be scrolled by the browser itself.** That happens when Polaris:
  - scrolls the chat to its newest message;
  - focuses the prompt box when the window opens;
  - calls `scrollIntoView` on anything inside the window.
- **Any of these scrolls the whole window's content up.** The drag bar moves out of sight above, and one line of the chat sits where the bar was.
- **With no bar there's nothing to drag or double-click.** The window is stuck.
- **The minimised height is remembered per browser** (localStorage `compass.polaris.window`). Opening the window restores the 18px height, and the scroll happens again, so it survives a restart.

The earlier guess (a text selection hijacking the drag) may also play a part, so the fix covers it too.

Workarounds given to Steve:
- `localStorage.removeItem('compass.polaris.window'); location.reload()` in the console;
- or Tab to "Resize Polaris" and use the arrow keys or Home.

## Behaviour

- **The drag bar is always the top of the window and always visible.** That holds whatever size the window is and whatever Polaris is doing. Nothing inside the window can scroll it away.
- **Minimised means only the bar shows.** Nothing is scrolled into view behind it. New messages, the prompt and Polaris working don't show through until the window is restored.
  - The bar may show a small dot or "Polaris is working…" so you know something happened.
- **Double-clicking the bar** toggles between minimised and the last height, every time.
- **Dragging works straight afterwards**, and double-clicking never selects text.
- **A remembered size can never lock you out:**
  - If the stored state is unreadable or taller than the screen, the window opens at the normal quarter-screen height.
  - If it was minimised with no height to go back to, restoring opens it at the quarter height.
- **"Reset window size"** in the window's options puts it back to the quarter height without using the console.

## Notes for the build

- **`PolarisWindow.tsx`:**
  - Use `overflow: 'clip'` on the section instead of `hidden`. `clip` can't be scrolled programmatically.
  - Or make the grip a fixed-position sibling outside the clipped content, so no scroll can move it.
  - Reset `scrollTop = 0` on the section as a belt and braces.
- **While collapsed:**
  - Don't auto-focus the prompt.
  - Don't run the chat's scroll-to-bottom. Run it once on restore instead.
  - Make the chat body `inert` (or `visibility: hidden`), so Tab and `scrollIntoView` can't reach into it.
- **The grip:**
  - add `userSelect: 'none'`;
  - call `preventDefault()` in `onGripDown`;
  - add `onDragStart` → `preventDefault`;
  - on `onLostPointerCapture`, set `dragging.current = false`.
- **`readStored`:** validate the stored state; fall back to `startHeight()` when `last` ≤ GRIP_HEIGHT or the value doesn't parse. The existing `clampHeight` already handles a height taller than the screen.
- **Tests:**
  - vitest: collapsed, the content is inert and the grip is the first visible element;
  - a scroll attempt on the section leaves `scrollTop` at 0;
  - each bad stored state opens a usable window;
  - "Reset window size" works;
  - the grip is `user-select: none` and its pointerdown is default-prevented.
  - In a real browser (the headless Chromium harness):
    - minimise, send a prompt and reload; the bar is still visible;
    - double-click then drag works.
- Independent: no API change and no migration.
