ADR 0169 §5. The guard that stops a rolled-back database re-running real account changes.

**Chain:** on the chain — migration + API.

**What people see**

- While on hold, a banner tells everyone that Compass has been restored and outbound work is paused. People can read and edit.
- **Admin ▸ Backups ▸ Review** lists what would run:
  - each access change and account deletion that was due, to **run** or **cancel** individually
  - email and notifications waiting
  - scheduled jobs paused, including the nightly privacy retention run
  - tokens, people and privileges that differ from the live data before the restore. After a complete failure, all API and assistant tokens and privileged roles, to confirm
  - files the restored records point at that no longer exist, and files nothing refers to
- **Release the hold** is refused while any account deletion is undecided. It asks for a typed confirmation and is recorded in the activity log.

**Done when**

- On a restored database holding an approved, already-run access change and a cancelled account deletion, **neither runs** across several sweeps. Each runs only if an Admin chooses it.
- While on hold, no integration write, email or scheduled job happens. Proved by a test over every outbound path and every scheduled job, so a new one cannot be forgotten.
- A legal hold can be placed during the hold, before the retention run next happens.
- Restarting every pod, or losing Valkey, does not lift the hold.
- Mail due before the restore is not sent on release unless the Admin chose it.

**Technical notes**

- Store the hold **in the database**, written as part of the restore before any service reconnects.
- The sweep to guard: `sweep_due_access_work` (`tasks/access_execute.py`, every 5 minutes; "late is not skipped"), plus `_claim_deletion`, which only checks database columns. The existing per-integration pause (`core/integrations/gates.py`) lives in the database and can be overwritten, so don't rely on it alone.
- After release, Compass's own later changes have no ledger rows, so directory sync would report them as unrequested. Handle or flag those in the review.
