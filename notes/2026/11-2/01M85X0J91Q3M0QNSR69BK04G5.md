Fix-forward on COM-2118, found while fixing COM-2119.

**Chain:** independent unless it needs an API change.

**The defect**

Before a restore, Everything checks that someone could release the hold afterwards. It counts any active Admin in the copy, even one who can't sign in: a Microsoft account when Microsoft sign-in will be off after the restore, or a local account with no password. Reset mail is refused during a hold. So a restore can bring Compass back on hold with nobody able to sign in from inside the app, leaving only the command-line create-admin.

Keep audit logs (COM-2119) now counts only Admins who can really sign in. Everything should use the same rule.

**Done when**

- Everything refuses, naming the reason, when no Admin in the restored data could sign in afterwards. The rule matches Keep audit logs: a Microsoft account counts only if Microsoft sign-in will be on (or it has a password, depending on what its groups give), and a local account only if it has a password.
- The complete-failure recovery (COM-2120) doesn't refuse, because there is no live data to compare against and the runbook gives the create-admin route. Instead it says plainly at the end that nobody can sign in, and how to fix it.
- A test on real Postgres fails on the old code and passes on the new.
