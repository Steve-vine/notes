Fix-forward on COM-2117, found by the COM-2124 rehearsal (screenshot `~/compass-uat/backup-and-restore/COM-2124/screenshots/S2/hold-review.png`).

**Chain:** independent unless the review's API response changes, in which case it joins the chain.

**What happened**

After a restore, Admin ▸ Backups ▸ Review listed every account deletion as "Delete the account of ?" and every access change as "Membership change: ?". Only a joiner carries a name on its request, and the review doesn't look the person up, so the Admin can't tell whose account they are deciding to delete.

**Done when**

- Every item names the person (display name and email or username) and what will change: the group or role, and which system (Entra, AD, Exchange).
- The person is looked up in the restored data and the directory mirror. If they can't be found, the item says so plainly ("a person no longer in the directory, id …") rather than "?".
- The same names appear wherever the review lists people: tokens, privileged roles and handovers.
- A test with a membership change and a leaver whose request carries no name shows both names in the review.
