**On the chain** (new source, settings, API). ADR 0188. After COM-2215. Steve, 27 Nov 2026: "automatic for exact matches".

## What people see
- **Vulnerabilities** gains a source, **Version match**: "Raised by Compass because the server's installed version is one the vendor or distribution says is affected."
- For every **exact match with a fix available** (Windows from COM-2213, Linux from COM-2215), Compass raises **one vulnerability per CVE per server** in the register: title and severity from the Security Feed item, the server as its system, and in its details the installed version, the fixed version (or KB) and the advisory. Due dates and owners follow the register's existing rules (ADR 0129).
- **If the server already has that CVE** (for example from Nessus), Version match is added as another sighting on the same issue; no duplicate.
- **It closes by itself as Fixed** ("confirmed by Version match: now 3.0.2-0ubuntu1.18") when the server's next read shows the fixed version or the package gone. It closes **only for servers that reported** in that read: a server that's Not reporting closes nothing.
- **It reopens** (same VUL number, reopened count) if a later read shows an affected version again.
- A person's **Accepted** or **False positive** is respected: Compass doesn't reopen or re-raise it while that decision stands (existing register behaviour).
- **"No fix yet" is never raised** (it stays on the server's Patch level and the Security Feed).
- On the Security Feed, an exact match that has been raised reads **Affects us — raised automatically**, links to its vulnerabilities, and **creates no Security Feed action** for the managers (the vulnerability is the work).
- **Per-company settings** (Vulnerabilities settings): **Raise vulnerabilities from exact matches** (on by default) and **Only from severity** (default: all).
- Possible matches (other software) are unchanged: a person confirms and raises them as today.
- The first run for a company can raise many at once; it's done in the background and the register says "Compass raised 214 vulnerabilities from exact matches" in its activity.

## Notes (technical)

Reconcile handles fixed / reopen.
- Run after each server's read and after each Security Feed read that changes distribution or Microsoft fixes (debounced per company). Celery, idempotent, IDs only, task label.
