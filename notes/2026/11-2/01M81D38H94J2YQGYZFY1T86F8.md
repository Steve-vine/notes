Sprint "Attestations - Tweaks and Improvements". Builds on reading groups (COM-2097). Raised by Steve while testing Attestations, 2026-11-22: with 91 roles it's hard to track who's assigned what.

## What people see
- **Attestations ▸ Who reads what** (a new tab): documents down the side, reading groups across the top. Each cell shows that the document is assigned to that group, with its cadence and how many of the group are compliant. Click a cell to open the assignment.
  - Filter by document or group; a search box; export to spreadsheet.
  - A row for a document assigned to nobody is flagged, so an unassigned policy is easy to spot.
- **On a person** (the Compliance tab's person view, and the person's page in Access Control): "Asked to sign", listing each document with **why**, e.g. "Information Security Policy, because they're in All staff and All managers". Each document shows its due date and status, signed or outstanding.
- Polaris can answer "who has to read the Acceptable Use Policy?" and "why is Sam being asked to sign the Remote Working Policy?".

## Implementation notes (technical)
- Read-only; reuses the stored group membership and request reasons from COM-2097. A new read route for the matrix; extend the person attestation read with the groups behind each request.
- Independent once COM-2097 is on main (likely no migration; adds a read route, so join the chain if the API changes).

## Done when
- The matrix matches the assignments on each group's page.
- A document assigned to no group is flagged.
- A person in two groups that both assign the same document shows it once, with both groups named as the reason.
