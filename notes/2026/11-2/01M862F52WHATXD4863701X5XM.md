Fix-forward on COM-2115, found by the COM-2124 rehearsal.

**Chain:** independent unless it needs an API change.

**What happened**

On the rehearsal's file store (MinIO from December 2022), taking a copy failed. The store rejects the newer upload checksums the S3 library now sends by default. The screen said only "Something went wrong while it was being made." AWS S3 in production isn't affected, but the chart README lists MinIO as a supported store, and other S3-compatible stores (older MinIO, Ceph, some appliances) behave the same way.

**Done when**

- Copies work against an S3-compatible store that doesn't accept the newer checksums. The client only sends or requires checksums when needed, which is the documented setting for such stores, and AWS S3 behaves exactly as before.
- Evidence uploads and every other use of the store work against such a store too, or the README stops claiming it's supported.
- A failed copy says why, in words an Admin can act on (for example "The file store refused the upload: …"), with the full detail in the logs and no credentials in either.
- A test reproduces the old store's refusal and passes after the fix.
