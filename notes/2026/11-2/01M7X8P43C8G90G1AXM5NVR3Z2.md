    What changes:
    - A newly added Word, Excel or PowerPoint file gets a PDF copy made in the background a few seconds after it's added, by any route. Its preview says "Preparing a preview…" until the copy is ready, then shows it as it would print, without a reload.

    How it's made: LibreOffice runs inside the existing server image, used only by the background worker. That adds about 150 MB to the image (290 → about 440 MB compressed). A conversion uses about 210 MB of memory. Each file is treated as untrusted: a fresh profile each time, macros off, no network access, a 90-second limit and a 300-page limit. All of this was tested with real LibreOffice.

    To run after it's deployed (once per environment): python -m compass_api.cli backfill-preview-copies, in the API pod. It's safe to run again.

    Calls for you to overturn:
    - LibreOffice in the main image rather than a separate converter service (that would mean another image and more chart changes for little gain).
    - A file over 300 pages is refused rather than shown cut short.
    - Spreadsheets preview as they'd print, not one page per sheet.
    - Older Office and OpenDocument formats get copies too.
    - Archiving keeps the copy, so archived evidence still previews.

Built to the ADR in COM-2038, after COM-2047. Steve chose this over a best-effort or no preview for Office files (2026-11-20), accepting a bigger server image.

**What people see**
- A Word, Excel or PowerPoint file previews (COM-2047) as it would print. Compass makes a PDF copy in the background a few seconds after upload. Until then the preview says "Preparing a preview…" and updates when it's ready, without a reload.
- **The original is the evidence.** Download, audit packs and exports give the original file. The PDF copy is only for looking at, and it isn't a piece of evidence of its own (no EVD ID, nothing in the register).
- If a copy can't be made (password-protected, damaged, too long to convert), the preview says "No preview for this file" with the reason, and Download. Nothing else about the evidence changes.
- **Existing Office evidence** gets its copy once, in the background, after this is deployed.
- Archiving or deleting the evidence for good takes its copy with it.

**Implementation notes**
- Convert in a Celery task (idempotent, takes the file's id; give it a label in core/task_labels.py). Convert with LibreOffice headless in the worker image, or a separate converter service in the chart: the PR says which and why, with the image-size cost. Arm64 builds need it too.
- Treat the file as untrusted: no macros, no network, a time limit, and a page limit. Store the copy beside the original, with the same company and permissions. Migration for where the copy is kept and its state (preparing / ready / failed with reason).
- The backfill runs as a one-off task, not at container start and not in the migration.

**Done when**
- A newly uploaded Word, Excel or PowerPoint file previews as a PDF within seconds, while Download still gives the original.
- Existing Office evidence previews after the backfill.
- A file that can't be converted says why and still downloads.

On the chain: migration and API change.
