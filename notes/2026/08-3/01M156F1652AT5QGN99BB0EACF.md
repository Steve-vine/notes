A business role is currently a **decoration** on the graph, not a subject. The overlay (ADR 0048 §3, `api/v1/directory.py` graph endpoint) only tags roles onto groups the walk already reached — it never widens the walk — and `AccessGraphPage.onOpen` deliberately sends a role node to its matrix page rather than re-rooting, because a role is not a directory object.

Make it a subject. "Show me Finance Approver" — the groups it hands out and everything those pull in by nesting — is a small, bounded picture whose *shape* is the finding: a role reaching further than whoever wrote it intended. That is the case a node-link diagram is actually good at, unlike a person and their 170 groups (COM-305's ring cap keeps that drawable at 12/ring, but the first twelve alphabetically is an arbitrary sample — legible and unrepresentative).

* **Endpoint**: accept a business-role id as `root`. Root resolution today resolves user / group / device against the mirror; a role root seeds the frontier from its `BusinessRoleGroup` groups at depth 1 via `grants` edges, then the existing BFS runs unchanged from those groups. Company-scoped and `status == active`, `deleted_at is None`, like the overlay. Unknown / other-company role → the same honest 404 as a vanished object.
* **Root picker**: a "Business roles" section alongside Users and Groups, from the existing `useBusinessRoles` hook, company-scoped.
* **Re-rooting**: with roles now rootable, a role node's body re-roots like any other; the icon keeps opening the matrix page. Deep-link `/access/graph?root=<business_role_id>` as usual.
* **Defaults when the root is a role** — the point of the task is testing whether a narrower framing reads better, so: direction `down`, and users + devices off in the object filter. A role's picture is role → groups → nesting; the people are the fan-out that made the canvas unreadable in the first place. Persisted prefs still win once touched.
* **Entry point**: "View in graph" on the role detail / matrix page (`RoleDetailPage`), matching the group and user modals.
* ADR 0048 §3 amendment — the overlay was specified as decoration-only; a role becoming a legal root changes what the endpoint accepts and what a role node does when clicked.
* Tests: role root seeds its groups, non-active/other-company role 404s, picker section, role-root defaults, node-body re-root vs icon navigation.

Refs: ADR 0048 §3; `core/directory_graph.py`, `api/v1/directory.py`; `src/access/AccessGraphPage.tsx`, `graph/graphMeta.ts`, `RoleDetailPage.tsx`.
