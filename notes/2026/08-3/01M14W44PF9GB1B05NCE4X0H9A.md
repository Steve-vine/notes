    Done and merged to main — PR #500.

    `GET /reports/definitions/{id}/run` pages and sorts in the database and reports `total` as the whole answer rather than the page, so a reader sees "1–50 of 812". `GET .../download` returns the whole answer as CSV or PDF through the ADR 0024 renderer unchanged, with the preamble the task asked for: report, question, the sentence that was asked, company, run-at and row count — and a TRUNCATED line on the face of the file when the cap bit.

    That sentence comes from one `describe()` in the runner, shared with the report's page, the wizard's summary and the PDF subtitle. Four renderings would have been four chances for a download to describe a different question from the screen it came off.

    Two things worth flagging:

    **The response carries both the typed rows and the rendered ones.** That is not redundancy — the table renders `text_rows`, which is exactly what the CSV renders, so the screen and the download cannot disagree about what a null means. Both say "Unknown"; neither leaves a blank cell, which every spreadsheet reader takes for "no".

    **The company a report runs for is the definition's own when it has one**, and the caller's parameter only when it does not (a standard report belongs to none, so it runs for whichever company the reader is looking at). Passing a company that contradicts the definition's is a 409 — an Acme report run over another company's data would be a boundary crossed by a query string, which is exactly the shape ADR 0062 §6 refused saved SQL to prevent. A company-scoped subject with no company is a 422 rather than a silent widening.

    A definition naming a field the catalogue no longer declares returns 409 with the reason rather than a 500. CI is meant to catch that first (COM-493 validates the seeded library on every build), but a reader who hits it gets something they can act on.

    As the task anticipated, the ad-hoc download became a recorded run once COM-494 landed — see that task's note for why the download is a GET that writes.

ADR 0062 §5, first half. Execute a stored definition and hand back the answer.

One endpoint takes a definition id and returns a paginated result: the columns as the definition ordered them, the rows, the total, and whether the row cap truncated it. Sorting and paging happen in the database, not in the browser — some of these subjects are tenant-sized.

CSV and PDF reuse the ADR 0024 renderer unchanged. Both carry a preamble stating what was asked and when, in the same spirit as the coverage rule stamped on the coverage report: a spreadsheet found on a disk in six months should be able to say what question it answers and which company it was run for.

Reads follow the same rule as the rest of Access Control — any authenticated user who can see the subject can run a report over it. A report grants no visibility its subject does not already grant.

Ad-hoc runs still produce a run record (COM-494) once that lands; this task returns the result and the download, nothing persisted.
