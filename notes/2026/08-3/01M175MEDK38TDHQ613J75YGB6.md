**Reported:** the domains list is hard to read — the CSF function headings (Govern, Identify …) are interleaved with the rows and the shading makes some headings read light and some dark.

Replace the heading rows with a **"CSF Function" column carrying a badge on every row**.

## What's there now

`pages/DomainsPage.tsx:58-89` — four columns (Domain, Code, Controls, Status) with a full-width heading row injected before each group:

```tsx
<Table.Tr style={GROUP_HEADING_ROW_STYLE}>
  <Table.Td colSpan={4}>
    <Text size="sm" fw={700} tt="uppercase" c="dimmed">
      {fn ? FUNCTION_LABEL[fn] : 'No function set'}
    </Text>
  </Table.Td>
</Table.Tr>
```

Zebra striping was **already removed** for this exact reason — the comment at `:55-57` records that CSS striping counts every row, so the interleaved headings restarted the alternation at each group, and COM-465 chose shaded heading bands instead. Those bands are what's now reading inconsistently.

## The change

- Add a **CSF Function** column rendering `FUNCTION_LABEL[domain.function]` as a `Badge` in `DomainRow` (`:108-121`).
- Delete the heading row and the `Fragment`/`groupByFunction` wrapper from the table body (`:71-88`).
- **Bring zebra striping back.** With every row a data row, the reason it was dropped is gone — and consistent alternation is the readability win being asked for here. `<Table striped highlightOnHover>`.

**Don't delete `GROUP_HEADING_ROW_STYLE`.** It's shared — `components/GroupHeading.tsx:24` and `pages/FrameworkDetailPage.tsx:892` (PCI's numbered requirements, ISO 42001's annex objectives) still use it. Only this page stops using it.

## Decide: does the list stay in function order?

Removing the headings removes the grouping, but not necessarily the **order**. Today `groupByFunction` (`:97-106`) deliberately sorts by CSF order rather than alphabetically — the comment at `:68-70` explains why: *"a reader should meet governance before detection, because the second only means anything inside the first"* (COM-423).

**Recommendation: keep that ordering as the default sort.** The list still reads in the intended sequence, the badge names each row's function, and nothing is lost but the interleaved bands. Sorting alphabetically by domain name instead would discard a deliberate choice; worth a conscious decision either way.

## Badge details

- **Domains with no function.** `domain.function` is nullable — today those fall into a "No function set" group at the end. As a badge, that wants a neutral grey treatment or an em-dash rather than a coloured badge reading "No function set", which would draw more attention than the ones that *are* set.
- **If the badges are coloured per function**, a bare colour name makes Mantine's `autoContrast` a silent no-op — the shade has to be explicit, or light-coloured badges end up with unreadable text. Six functions also means six colours competing on one screen; a single neutral badge with the function name may read better than a rainbow. Worth trying both.
- Pill sizing rules live in `theme.ts`, not the call site — `brief/information-architecture.md` §"A pill shows its whole label". Six labels of differing width ("Govern" … "Identify") will want a minimum width there if they're to line up down the column.
