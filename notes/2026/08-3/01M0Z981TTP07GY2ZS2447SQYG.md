Two things are wrong with the Cyber Essentials library, and one of them would
put a false claim in a report.

**It is not Plus.** The framework is stored as "Cyber Essentials Plus" but holds
the 31 self-assessment requirements across the five technical controls. Cyber
Essentials Plus is the *audited verification* of those same controls, with its
own test specification. Anyone reading a Compass report would believe the company
holds a certification it has never been assessed for.

**It is a version behind.** The stored requirements are the Willow question set /
Requirements for IT Infrastructure v3.2 (28 April 2025). Since **27 April 2026**
new certifications are assessed against **v3.3 with the Danzell question set**.

Two requirements are materially wrong as written:

- `UAC5` says "implement multi-factor authentication **where available**". Under
  Danzell, MFA is **mandatory on all cloud services**, and where a cloud service
  offers MFA and it is not in use the applicant **automatically fails**.
- `SU4` says apply high and critical updates within 14 days. Under Danzell that
  window is an **auto-fail**, not a target.

Danzell also introduces a formal definition of a cloud service (on-demand,
scalable, shared infrastructure, internet-accessible, accessed via an account
that stores or processes your data) and changes scoping, backups, user access
control and application development.

## What changes for the reader

The framework reads "Cyber Essentials", version 3.3 (Danzell), effective 27 April
2026. Willow stays as a superseded version so an assessment made before April
still says what it was made against.

The requirements gain the **scope** rules that CE actually tests and Compass has
never held — BYOD, home working, the cloud shared-responsibility model, and
sub-set scoping. Most CE failures are scoping failures, and today they are
invisible.

Requirements that carry an automatic failure are marked as such, because "not
met" on an auto-fail requirement is not a gap to schedule — it is a failed
certification.

## Implementation

- Depends on the framework-versions task: Willow becomes `superseded_by` the new
  row rather than being edited in place.
- New `data/frameworks/cyber-essentials-3-3.csv` from the NCSC Requirements for
  IT Infrastructure v3.3. Descriptions ship in the CSV — CE is openly published,
  so the blank-only backfill applies (ADR 0028).
- Add the scope requirements as a sixth group. They are requirements, not notes.
- `auto_fail` flag on the requirement, surfaced in the gap list and the coverage
  view. Small addition, but it changes how a reader treats the row.
- Re-map to Core after the control rewrite lands — do not carry the Willow
  mappings across unexamined, particularly `UAC5`, whose meaning has changed.

Tests: both versions coexist; Willow is readable and not assessable; an auto-fail
requirement is visibly distinct in the gap list.
