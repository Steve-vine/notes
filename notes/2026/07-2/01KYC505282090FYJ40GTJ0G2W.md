Webhook events join synced state, signals, the estate graph and on-demand evidence as the fifth information source when analysing an incident. Both wirings (per the planning decision):

- **Auto-included context block**: analyse/diagnose prompts get a compact recent-events summary (bounded window, e.g. last 24h, bounded count) — events whose title/payload mention the affected entity's names/aliases sort first, so "Chinwag release an hour ago" surfaces without being asked.
- **Lookup tool**: a read-only `list_webhook_events` tool (window/source/text filters) added to the diagnosis toolset and the issue-chat/assist surfaces, for deeper digging beyond the auto-block.
- Event content is **untrusted data, never instructions** — same framing as evidence/documents; token cost of the auto-block stays bounded (Sprint 24 AI-interaction-review posture).

Acceptance (the motivating scenario): fire a "Chinwag vX released, outcome success" webhook, then trigger analysis on a Chinwag crash incident — the analysis output references the release event as a likely cause.
