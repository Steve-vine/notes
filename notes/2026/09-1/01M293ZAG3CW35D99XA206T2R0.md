Smoke finding, 2026-09-11: nobody thinks of an inventory review cadence in days. Months everywhere.

* **Settings** (Inventory settings card): `container_review_days` / `data_asset_review_days` → `container_review_months` / `data_asset_review_months` (default 12). Migration: add the new columns, backfill `round(days / 30)` with a floor of 1, drop the old. Append-only, one head.
* **Per-asset override**: `review_interval_days` → `review_interval_months` on both `containers` and `data_assets`, same backfill; the modal field reads "Review interval (months)", description "Blank uses the register default", under the field (the sub-heading task).
* **Due-date arithmetic** (COM-672's Beat task and the *Next review* column): `last_verified_at + N months` (calendar months, `dateutil.relativedelta` — not `N*30` days, so a 12-month interval lands on the same date next year). Dedupe key for the review-due action is unchanged (asset + due date).
* CSV template column renames to `review_interval_months`; the importer accepts it.
* API schemas and `schema.d.ts` regenerate (drift script). Tests for the settings card, both modals and the Beat task's arithmetic (a 31 Jan + 1 month case).

**Acceptance**: settings show 12 months by default; an asset with a 6-month override verified today shows next review six calendar months out; existing overrides survive the migration in months.
