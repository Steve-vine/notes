Asked for by Steve while smoke-testing, 2026-09-08.

## The rename

The gap page's **Ownership & progress** box is renamed **Progress**. Owner, status and target date stay in it as they are.

## Notes

Directly below Status and Target date, a **Notes** field: full width, three rows, always editable by anyone who can edit the gap, read-only for everyone else. It is a single running note on the gap — the current position, a reminder, whatever the owner wants to keep in view — as opposed to the description (what the gap *is*) and the comments (who said what, when). It saves when you click away from it, the way Status and Target date save on change; there is no Save button. Blank is fine.

## Comments

Below Notes, the Progress box gains a comment thread — the running account of what has been done about the gap.

**Writing one.** A full-width text box, three rows tall, with a **Comment** button beneath it. Anyone who can edit the gap can write a comment. Submitting clears the box and the comment appears above it. A blank comment cannot be submitted.

**Reading them.** Each comment is its own block above the box, newest first, showing who wrote it and when (date and time) on the top line, then the text. Anyone who can see the gap can read the comments.

**Changing one.** A comment carries **Edit** and **Delete** buttons for its author, and for an **administrator** on every comment (Steve, 2026-09-08). Edit turns the text back into a box in place, with Save and Cancel; an edited comment shows "edited" beside its time. Delete asks for confirmation, then removes the comment from the thread for good. Nobody else sees the buttons.

Comments are text only — no attachments, no mentions, no notifications. They are not part of the Actions queue or the activity log: they are correspondence, not a state change, the same reasoning as the vendor request transcript.

**Box order, top to bottom:** Owner · Status + Target date · Notes · comments (newest first) · comment box + button.

*Implementation notes.*

**Notes column.** `Gap.notes: Mapped[str | None] = mapped_column(Text, default=None)`; append-only migration adding the nullable column; `notes: str | None` on `GapUpdate` and `GapOut` in `schemas.py`. It goes through the existing `PATCH /gaps/{gap_id}` — no new endpoint. Gaps *are* in the activity allowlist, so the change is logged like any other field edit. Frontend: `Textarea rows={3} autosize={false} label="Notes"` in the Progress card, local `useState` seeded from `gap.notes`, `onBlur` → `save.mutate({ notes: value.trim() || null })` only when it differs from `gap.notes` (no PATCH on a no-op blur, and the "Gap updated" toast fires only when something changed). `disabled={!canEdit}`. Hooks-lint: seed the local state with a `key={gap.id}` on the component or via `useState(gap.notes ?? '')` at mount — not with a setState-in-effect.

**Comment model.** `models/gap_comment.py` — `GapComment(Base, UUIDPrimaryKeyMixin, TimestampMixin, SoftDeleteMixin)`: `gap_id` FK → gaps (indexed), `company_id` (denormalised for scoping, as gaps carry it), `author_id` FK → users nullable + `author_name` snapshot (the `VendorRequestMessage` pattern, so a departed user still has a name), `body` Text. `updated_at > created_at` is what "edited" reads from. Same migration as the notes column. **Not** in the ADR 0023 activity allowlist — see the `vendor_request_message.py` docstring for the reasoning to cite.

**API** (`api/v1/gaps.py`, all under `/gaps/{gap_id}/comments`):
- `GET` list → `list[GapCommentOut]` (id, author_id, author_name, body, created_at, updated_at) — `require_posture_view`, ordered `created_at desc`, live rows only.
- `POST` `{body}` → 201 `GapCommentOut` — `require_posture_gaps`; body stripped, 422 if empty.
- `PATCH /{comment_id}` `{body}` — `require_posture_gaps` **and** (`author_id == user.id` **or** `user.is_admin`), else 403. Same `is_admin` flag `require_admin` in `core/auth.py` guards on (ADR 0067 §5, "holds every permission").
- `DELETE /{comment_id}` → 204 — same rule; soft delete.
The gap must be live and in the caller's company (`_get_or_404`). Docstrings are OpenAPI contract — run the drift script, commit `schema.d.ts`.

**Frontend** (`GapDetailPage.tsx`). Rename the card heading. Below the `Group grow` of status/target date: the Notes `Textarea`, `Divider`, then a `Stack` of `GapCommentCard`s (author `Text fw={500}` + `Text c="dimmed" size="sm"` for the timestamp via the existing date formatting helper + "· edited" when `updated_at !== created_at`; body `Text style={{whiteSpace:'pre-wrap'}}`; Edit/Delete as `Button variant="subtle" size="xs"` shown when `comment.author_id === me.id || usePermissions().isAdmin` — the flag `ActivityHistory.tsx:33` already reads), then the composer: `Textarea rows={3} autosize={false}` full width with a `Button` "Comment" disabled while blank or submitting, rendered only when `canEdit`. Delete goes through the confirm modal the rest of the app uses. React Query: `['gap-comments', gapId]`, invalidate on each mutation. Hooks-lint note: no setState in effects — reset the composer inside the mutation's `onSuccess`.
