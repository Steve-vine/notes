## The rename

The gap page's **Ownership & progress** box is renamed **Progress**. Owner, status and target date stay in it as they are.

## Comments

Beneath those fields, the Progress box gains a comment thread — the running account of what has been done about the gap.

**Writing one.** A full-width text box, three rows tall, with a **Comment** button beneath it. Anyone who can edit the gap can write a comment. Submitting clears the box and the comment appears above it. A blank comment cannot be submitted.

**Reading them.** Each comment is its own block above the box, newest first, showing who wrote it and when (date and time) on the top line, then the text. Anyone who can see the gap can read the comments.

**Changing one.** A comment carries **Edit** and **Delete** buttons for its author. Edit turns the text back into a box in place, with Save and Cancel; an edited comment shows "edited" beside its time. Delete asks for confirmation, then removes the comment from the thread for good. (Assumption: only the author can edit or delete their own comment — a thread is a record of what people said, so nobody rewrites anyone else's words. Say if admins should be able to delete.)

Comments are text only — no attachments, no mentions, no notifications. They are not part of the Actions queue or the activity log: they are correspondence, not a state change, the same reasoning as the vendor request transcript.

*Implementation notes.*

**Model.** `models/gap_comment.py` — `GapComment(Base, UUIDPrimaryKeyMixin, TimestampMixin, SoftDeleteMixin)`: `gap_id` FK → gaps (indexed), `company_id` (denormalised for scoping, as gaps carry it), `author_id` FK → users nullable + `author_name` snapshot (the `VendorRequestMessage` pattern, so a departed user still has a name), `body` Text. `updated_at > created_at` is what "edited" reads from. Migration append-only; **not** in the ADR 0023 activity allowlist — see the `vendor_request_message.py` docstring for the reasoning to cite.

**API** (`api/v1/gaps.py`, all under `/gaps/{gap_id}/comments`):
- `GET` list → `list[GapCommentOut]` (id, author_id, author_name, body, created_at, updated_at) — `require_posture_view`, ordered `created_at desc`, live rows only.
- `POST` `{body}` → 201 `GapCommentOut` — `require_posture_gaps`; body stripped, 422 if empty.
- `PATCH /{comment_id}` `{body}` — `require_posture_gaps` **and** `author_id == user.id`, else 403.
- `DELETE /{comment_id}` → 204 — same rule; soft delete.
The gap must be live and in the caller's company (`_get_or_404`). Docstrings are OpenAPI contract — run the drift script, commit `schema.d.ts`.

**Frontend** (`GapDetailPage.tsx`). Rename the card heading. Below the `Group grow` of status/target date: `Divider`, then a `Stack` of `GapCommentCard`s (author `Text fw={500}` + `Text c="dimmed" size="sm"` for the timestamp via the existing date formatting helper + "· edited" when `updated_at !== created_at`; body `Text style={{whiteSpace:'pre-wrap'}}`; Edit/Delete as `Button variant="subtle" size="xs"` shown only when `comment.author_id === me.id` — `useMe()` or whatever the page already uses for identity), then the composer: `Textarea rows={3} autosize={false}` full width with a `Button` "Comment" disabled while blank or submitting, rendered only when `canEdit`.
