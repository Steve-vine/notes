Found by the first staging deploy after COM-652 (run 34468155344, 2026-09-10 10:51):

```
UPGRADE FAILED: cannot patch "compass-valkey" with kind StatefulSet: spec: Forbidden: updates to statefulset spec for fields other than 'replicas', 'ordinals', 'template', 'updateStrategy', 'revisionHistoryLimit', 'persistentVolumeClaimRetentionPolicy' and 'minReadySeconds' are forbidden
```

**Cause.** `chart/templates/valkey-statefulset.yaml` stamps `volumeClaimTemplates[].metadata.labels` with the chart's *common* labels, which include `helm.sh/chart: compass-<version>` and `app.kubernetes.io/version: <appVersion>`. Kubernetes treats `volumeClaimTemplates` as immutable, so the first time either value changes — COM-652 turned `0.1.0`/`0.0.0` into `0.0.0-dev` — the patch is refused. Latent since the chart was written: it would have bitten the first chart version bump anyway, and under ADR 0071 (chart version = release version) it would bite **every production upgrade**, 0.1.0 → 0.1.1 included.

**Fix (this task, fix-forward).** The claim template's labels become the *selector* labels only (name/instance/component) — stable for the life of the release — with a comment saying why. The Deployments and the StatefulSet `selector` already use selector labels and are unaffected; the mutable `metadata.labels` of the StatefulSet itself keep the versioned set.

**One-off on staging**, because the live template already has the old labels and *any* change to it is refused: before the next staging deploy, `kubectl delete sts compass-valkey -n compass --cascade=orphan` — removes the StatefulSet object only; the running pod and the `data-compass-valkey-0` PVC stay; the recreated StatefulSet adopts the pod by selector and the PVC by name. Production never needs this: its first install will carry the fixed template.

**Also record**: the chart README hard rules gain a line — nothing versioned goes into an immutable field (StatefulSet selector / volumeClaimTemplates, Job selector, PVC spec).

**Acceptance**: `helm template` at two different `--version`/`--app-version` values renders identical `volumeClaimTemplates` for the Valkey StatefulSet; after the orphan-delete, the staging deploy of the fixed chart succeeds and Valkey keeps its data (the session store survives, users stay logged in).
