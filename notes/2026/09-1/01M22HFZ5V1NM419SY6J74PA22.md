Found by Steve while smoke-testing sprint 55, 2026-09-09. Follows COM-631.

On Admin → Appearance with the app in dark mode, the **Light** preview panel takes some dark-mode colours: most obviously the background, the row hover highlight, the row separator, and some of the pills. (The Dark panel in light mode is right only by luck.)

**Why.** The toolkit compiles each `light-dark()` colour into two rules keyed on an ancestor's colour-scheme attribute. Inside the light preview both the page's dark `<html>` and the preview's light wrapper match, so whichever rule is declared later wins — dark. Variables the preview sets are fine; component rules that read the ancestor are not.

**Change.** Each preview renders inside its own shadow root, where the page's ancestors are invisible to selectors: only the preview wrapper's scheme matches. The app's stylesheets are cloned into the shadow root so the components still dress; the nested provider's variables land inside it. No visible change beyond the panels now being faithful in both schemes.
