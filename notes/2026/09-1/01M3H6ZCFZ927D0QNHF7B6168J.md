Part of the on-premises AD sprint (ADR in COM-773). Today every joiner is created as a cloud-only account in Entra, which is wrong for a hybrid estate.

## What people see

- **Role editor: "New starters go in".** An OU, picked from the managed OUs (COM-778). Steve decided 2026-09-27: **one OU per business role**.
- **The AD card: a default OU** for roles that don't name one. If there's no OU at all, the joiner can't be created in AD, and the request says why before approval, not after.
- **A joiner in AD only or Hybrid is created in AD, in that OU**, with their name, username, details and a temporary password that must be changed at first sign-in. The password is handed over the same way today's cloud joiner's is. Groups and lists in AD are granted straight away (COM-779).
- **Hybrid: the cloud parts wait for the account to reach Entra.** Shared-mailbox access, cloud groups and lists, and Microsoft 365 groups show on the request as **Waiting for the account to reach Entra**. They complete by themselves when the account appears, and the request finishes then. If it hasn't appeared after a few hours, the request says so: *"not in Entra yet — is this OU in Entra Connect's sync scope?"*
- **A mover whose new role puts starters in a different OU is moved there.**
- **Several roles naming different OUs** (Steve agreed 2026-09-27): the account stays in the OU of the role it joined with, and is moved only when that role is replaced.
- **Entra ID only: unchanged**; joiners are created in the cloud as today.
- **Failures follow COM-773's rule.** AD set up but the create fails means **Failed** + **Retry**. A joiner can't be a to-do, because it has no route without AD.

## Notes (technical)

- **Create.** An LDAP add of `user` in the OU, with `sAMAccountName` (≤20 characters, unique — derive and de-duplicate it) and `userPrincipalName` (the suffix must be one Entra Connect syncs). Set `unicodePwd` over LDAPS, `pwdLastSet=0`, then enable (`userAccountControl`).
- **Adopt-by-UPN** (today's `_execute_joiner`) searches AD as well as Entra.
- **The wait state.** A subject state for cloud work pending the account's arrival, completed by the sync pass when the matched record gains an `entra_id` (COM-777). It reuses the sweep, not a new timer. Licences stay outside Compass, as today.
- **The move.** An LDAP modDN to the new OU, only when both OUs are managed. Track "joined-with role" on the holding so the rule above is decidable.

**Done when:** on staging, a joiner whose role names an OU is created there in AD. In hybrid, their mailbox access completes by itself after the sync, and the request then finishes. A mover between roles with different OUs is moved. A role with no OU and no default refuses clearly.
