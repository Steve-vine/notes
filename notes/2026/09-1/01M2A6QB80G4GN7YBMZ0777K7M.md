Smoke finding, 2026-09-12 (Steve): switching between Inventory ▸ Technology Assets and ▸ Data Assets, the tables do not line up — on the data tab the column headings start lower down the page and the rows are further apart.

Both tabs are built the same way in `InventoryPage.tsx` (a `ScreenFrame.Head` with filters, then a `Table highlightOnHover stickyHeader` of `LinkRow`s), so the difference is in the cells, not the frame. Measure in the browser first (computed height of `thead`, of one `tr` on each tab, and of the head block), then fix the cause — do not pad one table to match the other. Suspects, in order:

1. **The Personal data cell** wraps two pills in a `Group` (`gap={4}`); a flex container inside a `td` adds its own line box, and with `wrap` on it can go to two lines when the column is tight. Render the pills inline (`Group wrap="nowrap"` with `white-space: nowrap`, or no Group at all) and give pill columns `nowrap`.
2. **Text cells that wrap**: with ten columns, Owner / Processing role / Next review may wrap on the data tab at the widths Steve uses. Pill and date columns get `nowrap`; the name column is the one that may wrap.
3. **The head**: two filter selects on the data tab vs three plus a `Text` on the technology tab — check whether the removed scope line (the sibling task) already equalises the head height; if not, both heads use the same `align="flex-end"` group and the same select `size`.

Whatever the cause, the outcome is **one row treatment shared by both registers**: same pill component and size in every pill column, same `nowrap` policy, same vertical spacing. If a `Table` prop set (e.g. `verticalSpacing`) is chosen, it is set once for both. Compare against the Vendors and Risks registers so Inventory matches the rest of the app rather than just itself.

Tests: a test that both tabs render rows with the same cell structure for pill columns (no wrapping `Group`), and no regression in the existing sort/link tests. Visual check by Steve on staging.

**Acceptance**: switching tabs, the column headings sit at the same height and rows are the same height on both registers; no cell wraps to a second line at a normal desktop width.
