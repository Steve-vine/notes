Production went live 2026-09-19 deployed by Argo CD from `Moneypenny-Development/devops.application.compass` into namespace `compass-prod`. The compass repo still carries, as its production "worked example", a hand-run install into a `compass` namespace that was never performed:

- `scripts/infra/production/README.md` (the runbook), `postgres-cluster.yaml`, `external-secret.yaml`, `aws/setup.sh`
- `chart/values-production.yaml`
- the production row in `scripts/infra/README.md`, and the mentions in `chart/README.md` and `CLAUDE.md` ("production is env-production-uk-pri … installed by hand from the published chart")

**Do**: replace the production worked example with a short page saying how production is really deployed — the devops repo, the two Applications (`compass-prod-env`, `compass-prod-app`) and why two, the one-number-three-places upgrade — and delete the manifests and values file that describe the path not taken. Keep `aws/setup.sh` only if its record of the original plan is worth having; `examples/aws/s3-irsa.sh` is what was actually used. The CI `chart` job and `scripts/ci/check-chart-immutable-fields.sh` render `values-production.yaml` as one of their shapes: replace it there with a representative "existing Secret + S3 pre-seed" values file under `chart/ci/` so the shape stays covered. An ADR note on 0071 §7 ("production is installed by hand from the published chart") — it is now installed by Argo CD from the published chart.

**Acceptance**: nothing in the compass repo claims production is installed a way it is not; the CI chart job still covers an S3/existing-Secret shape; the devops repo is linked from `chart/README.md` and `scripts/infra/README.md`.
