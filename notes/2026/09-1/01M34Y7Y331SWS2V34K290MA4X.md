Not every mailbox is a property of a job. The one-off case — "give Alex the complaints@ mailbox while Sam is on leave" — happens today in the admin centre, outside approval and outside detection, exactly as group membership used to before the membership-change request (ADR 0061 §4, COM-449).

The **membership-change request grows to accept a shared mailbox** as the thing being joined or left, with the access kind (*can open*, *can send as*, or both) stated per line. Same shape otherwise: named principals, named target, a reason, the standard or expedited approval, the same execution path and the same per-subject outcomes as the role-derived changes.

The managed-mailbox boundary still applies: the request can only name a mailbox some role maps. (Mapping a mailbox to no role and requesting access ad hoc is the way to bring an unmanaged mailbox under governance without giving it to a job — the picker says so.)

**Screen.** The membership-change form's target picker offers shared mailboxes alongside groups, with the access toggles appearing when a mailbox is chosen. The request list and detail name the mailbox and the kind.
