    Done — PR #419 (`brief-421-codeblock-text-mismatch`).

    **The cause.** Inline code already matched: `.cm-md-code` in the live-preview theme mirrors the read view's `.markdown code` (mono, 0.9em, tinted). The *block* form only ever got `background: var(--hover)` — no font at all — so revealed fence source inherited `.cm-content`'s proportional body font at full size.

    **Measured, not guessed** (throwaway Vite lab driving a real `EditorView` with `livePreview`, torn down before commit):
    - revealed fence, before: `Inter … sans-serif`, 15px / 22.5px, text at x=15
    - rendered widget + read view: `ui-monospace …`, 13.5px / 20.25px, text at x=26

    **The fix.** `.cm-md-codeblock` now takes family and size from `.code-block pre code` in `theme.css` — the same rule the widget and the read view render through — plus the `<pre>`'s 0.75rem horizontal inset, so the code doesn't slide sideways as the caret enters either. After: 13.5px / 20.25px mono, text at x=26.25 vs the widget's x=26. Covers plain and language-tagged fences and the ``` marker lines.

    **Decided on the fly.**
    - Included the horizontal inset as well as the font. It's the same defect — revealed source not matching the rendered box — and fixing only the font would have left a visible 11px sideways jump on every click into a fence.
    - Written as `.cm-line.cm-md-codeblock`, not the bare class: the padding has to out-specify the app theme's `.cm-line { padding: 0 }`. First attempt used the bare class and the lab showed padding-left still 0 — that's why the quote and callout rules beside it are written the same way.
    - Source mode untouched: no live-preview decorations there, and raw markdown is the point.

    `npm run check`, `npm test` (323) clean. Frontend only.
