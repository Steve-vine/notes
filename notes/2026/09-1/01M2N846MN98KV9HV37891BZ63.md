Found 2026-09-16 on the first AWS staging install (env-staging-uk, release 0.2.0): every attachment upload returns 500 with `ValueError: Invalid endpoint: ` from botocore. `chart/templates/configmap.yaml` renders `S3_ENDPOINT_URL: ""` (and `S3_REGION: ""` when unset) unconditionally; `Settings.s3_endpoint_url` is `str | None` but an empty env var arrives as `""`, and `get_storage()` passes it straight to `boto3.client(endpoint_url="")`, which is rejected before any request is made. The IAM role, bucket and policy were all correct — checked by simulation.

Nobody had run S3 mode through the chart before (g5 staging uses a local volume); `values-production.yaml` carries the same empty `endpointUrl` and would have failed identically on the production install.

**Fix, both layers**
1. Chart: emit `S3_ENDPOINT_URL` and `S3_REGION` only when set (`with`), so an unset value is genuinely absent.
2. Backend: `get_storage()` treats empty strings as None for endpoint, region and the two keys — a values file, an ExternalSecret or a `.env` can all legitimately produce `""`. Unit test for the empty-string case.

**Workaround** until 0.2.1: `--set config.s3.endpointUrl=https://s3.<region>.amazonaws.com`.

**Acceptance**: a chart install with `storageBackend: s3`, a bucket and a region, and no endpoint, uploads and downloads an attachment; the rendered ConfigMap has no `S3_ENDPOINT_URL` key; the unit test covers `""` → default endpoint. Released as 0.2.1.
