Website ADR 0002. Mirror compass-website's `.github/workflows/ci.yml`: one workflow, with Actions pinned by commit SHA.

## Scope

- [ ] Push to `staging`, or any PR: check + build. Deploys nothing. Steve previews staging locally after `git pull`.
- [ ] Push to `main`: the same build, then `wrangler deploy` to `notuvia.com`. `main` only ever moves by fast-forwarding to `staging`.
- [ ] Also on `main`: `workflow_dispatch`, plus `repository_dispatch` from the app's release CI (NOT-483), so a release refreshes the live download and changelog.
- [ ] Deploys queue and never cancel. PR runs cancel superseded runs.
- [ ] Credentials `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` exist only in the deploy step.

## Manual steps (Steve)

- Check `notuvia.com` is in the same Cloudflare account as `notuvia.net`. Both zones use the same nameservers, which suggests it is.
- Create a Workers-scoped API token and set both secrets **from a real terminal**, not through the Claude session (on ISE a pasted token had to be rolled).

**Done when:** a push to `staging` builds green, and the deploy step is proven by the first production deploy (NOT-485).
