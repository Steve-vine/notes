Sprint "Secrets - New Module" (ADR 0141, COM-1563). Builds on COM-1575 (the GitHub integration). Split out of COM-1575 on 2026-11-03.

## What people see

- **Deploy keys as sources.** Generated by ▸ GitHub deploy key: pick a repository, then a key. Each key shows:
  - its title and GitHub's key ID;
  - created, and **added by** (a GitHub login);
  - **last used**;
  - **Can write** or Read only;
  - always **Long-lived**, because deploy keys never expire. Information only: nothing is raised for it (ADR 0141).
- **Fine-grained personal access tokens as sources.** Generated by ▸ GitHub token. Each token shows:
  - its name, and the person it belongs to (a GitHub login);
  - the repositories and permissions it has;
  - **expires**, or "No expiration" (then Long-lived);
  - **last used**.

  Classic tokens can't be listed by GitHub's API, and the source picker says so.
- **Not yet tracked.** Deploy keys and tokens that no secret uses join "Keys at a source, not yet tracked" (COM-1573), with Can write and Long-lived as information. They raise nothing.
- **Pairing.** `compass-source-key` = the deploy key's GitHub ID on a vault copy pairs it with the key.
- **One key, several copies, several users.** A single deploy key can be kept in AWS Secrets Manager and Azure Key Vault (and GitHub Actions) and used by pipelines in each. It's **one** secret, with one source, every copy under Kept in, and every pipeline under Used by.
- **Rotation proven** when Compass sees:
  1. a new deploy key on the same repository;
  2. **every** stored copy updated after it;
  3. the old key removed;
  4. the old key not used after the last copy changed.

  It's recorded as **Seen at source and store**, with no confirmation needed. The sentences follow COM-1572–1574. For a copy not yet updated: "Half done: 1 of 2 copies updated — Azure Key Vault ▸ kv-prod ▸ deploy-billing hasn't changed since 3 Mar".
- **Which pipeline still uses the old key?** GitHub records one "last used" for the key, not one per user. So the sentence is "Something still uses the old key (last used 6 Nov)". Where a vault's own last-read date points to one copy, Compass adds "The AWS copy was last read on 6 Nov" as a hint. It never claims more than it can see.

## Notes (technical)

- Endpoints:
  - `GET /repos/{o}/{r}/keys`: id, key, title, created_at, read_only, added_by, last_used;
  - `GET /orgs/{org}/personal-access-tokens`: owner, repository selection, permissions, token_expires_at, token_last_used_at.
  - Page through every repository the installation can see.
- Store the deploy key's public key fingerprint as well as its ID. It's public, and it lets someone recognise the key in GitHub's settings.
- The feature switch is **Secrets ▸ Deploy keys and tokens** on the GitHub tile (COM-1575).

**Chain:** on the chain (migration and API).
