Sprint "Secrets - New Module" (ADR 0141, COM-1563). This task is the frame. The tasks that follow add due dates, rotations, cloud reads and sources.

## What people see

- **Modules ▸ Secrets**, directly after Inventory, for anyone with *View secrets*. Company-scoped, so it carries the Company gate. Tabs: **Register**, then **Discovered** (filled by the AWS task) and **Settings** (for *Manage secrets*; filled by later tasks).
- **Register.** One row per secret:
  - SEC-N and name, kind, source, used by, kept in, and owner;
  - URL-backed filters for kind, source, owner, the system using it, and Retired;
  - sorting on every column.
- **Add secret** (needs *Manage secrets*):
  - **Name** and **Kind**: API key, access key, deploy key, token, client secret, certificate, password, or other.
  - **Generated by**: a vendor from the Vendor register, a technology asset, or a name typed in.
  - **Used by**: one or more technology assets.
  - **Kept in**: a place typed in ("1Password ▸ Ops", "Kubernetes ▸ billing/stripe"). Store entries Compass reads join this later.
  - **Owner**: a person.
  - **Created**, **Last rotated**, and **Expires**, or "Doesn't expire".
  - **Notes**.
- **There's no value field anywhere.** The form says "Never paste the secret itself". Any text field holding something that looks like a key is refused with "That looks like a secret, so Compass won't save it". It's caught by known prefixes (`sk_live_`, `ghp_`, `github_pat_`, `AKIA`, `xox`, `-----BEGIN`) and by long high-entropy strings.
- **The secret's page:** a Details card, then Generated by, Used by, Kept in, Owner, and History (the activity log). Edit and Retire need *Manage secrets*, or being its owner.
- **Retire** for a secret no longer in use. You give a reason. It keeps its history, drops out of the register's default view, and from then on is never due.
- **Elsewhere:**
  - a vendor's page gets a **Secrets** card ("Keys this vendor issued");
  - a technology asset's page gets a **Secrets** card ("Keys this system uses");
  - each card links to the secret.
- **Permissions:** *View secrets* and *Manage secrets*, in the permission catalogue. The built-in Admin gets both; the starter roles stay frozen.
