## What happened

Steve, testing Checks ▸ All checks (2026-11-14): some rows start with a check ID ("CHK-14 · …") and some don't. The ones with an ID are collected checks, which Polaris designed and someone approved. Each was given an ID within its company when it was proposed. The ones without are Compass's own built-in checks (MFA, dormant accounts, public storage, overdue vulnerabilities…). These are the same for every company and were never numbered, so the list looks inconsistent and Polaris can't name them by ID. Steve chose to number them as well, rather than label them as Compass's own.

Today the table shows `ref · name` when a check has a ref and just the name when it doesn't (`ChecksPage.tsx`). Built-in checks have no ref (`core/checks`).

## What people see

- Every row on All checks starts with a CHK number, both built-in and collected checks. The same goes everywhere a check is named: its own page, the Overview, Settings, a control's Evidence tab, and the gaps a check raised.
- Numbers are per company, as now. Existing collected checks **keep the numbers they have**, because people and Polaris already refer to them. Each built-in check gets the company's next free number, in a fixed order, and keeps it from then on. A new company gets its built-in checks numbered first.
- A number is never reused. A built-in check that's switched off keeps its number, and so does one that's later retired.
- Polaris names built-in checks by their ID too, and "CHK-n" finds any check (get / run a check by ID, search).
