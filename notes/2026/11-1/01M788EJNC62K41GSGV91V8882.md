**Why.** When Polaris reads a pen-test report, Compass suggests a system for each finding from what it knows then: names, aliases, discovery and matching rules. Those suggestions are fixed at that moment. On 2026-11-12 Steve added the external IPs from the SAP-1 report (Wrexham external, 13 findings, still *being reviewed*) as aliases on the assets behind them, e.g. 38.101.210.154 on AST-49 CVX-DASH-NEXTPBX. The report's findings didn't pick them up. Reading the report again isn't a way round it, because proposing adds findings rather than replacing them, so it would duplicate them.

**What it should do.**
- While a report is **being reviewed**, the suggested system for each finding the person hasn't settled yet is worked out again whenever what Compass knows changes: an asset's name or aliases, a discovered resource attached or detached, or a matching rule added or changed. (Or simply each time the review page is opened, whichever is simpler; decide when building.) The same matching is used as at proposal time (`pentest._suggest`).
- **A person's choice is never overwritten.** A finding whose systems someone set, accepted or cleared keeps them. Only untouched suggestions move.
- A **confirmed** report is left alone: its vulnerabilities are already in the register.
- The review screen says when a suggestion is new since the person last looked, e.g. "Suggested now: AST-49, from its alias 38.101.210.154".

Independent, unless it needs a column to tell "suggested" from "chosen". If so, it's on the chain.

**Done when:**
- With a report under review whose finding names an IP no asset has, adding that IP as an alias on an asset makes the finding suggest that asset, without reading the report again.
- A finding whose system a person has already chosen doesn't change.
- A confirmed report's findings don't change.
