Sprint "Secrets - New Module" (ADR 0141, COM-1563). Builds on COM-1573.

## What people see

- **Generated by ▸ AWS access key.** Pick an account, an IAM user, and one of their access keys. Each key shows:
  - its access key ID (an identifier, not the secret);
  - active or inactive;
  - created;
  - **last used**: the date, the service and the region.
- **Always Long-lived.** AWS access keys never expire. The pill and the age show; nothing is raised for it (ADR 0141).
- **Not yet tracked.** Access keys that no secret uses appear in "Keys at a source, not yet tracked" (COM-1573), with their age and last use. **"Never used"** and **"Not used in 90 days"** show as plain information, not findings. They help someone decide whether to retire a key.
- **Pairing.** `compass-source-key` = the access key ID on the vault entry pairs it.
- **Rotation proven** when:
  1. a new key is created for the same user;
  2. every stored copy is updated after it;
  3. the old key is deactivated or deleted.

  Recorded as **Seen at source and store**. The sentences:
  - **"There's a new access key, but the stored copy hasn't changed."**
  - **"The old access key is still active."**
  - **"The old key was used on 6 Nov, after the stored copy changed. Something still uses it."** This one keeps the rotation at *Finish rotation* until the old key is deactivated.

## Notes (technical)

- New reader declares `iam:ListUsers`, `iam:ListAccessKeys` and `iam:GetAccessKeyLastUsed`. The policy and the `docs/aws/` files regenerate. IAM is global, so read it once per account, not per region.
- The access key ID (`AKIA…`) is an identifier and safe to store. The key-shaped-text guard (COM-1564) must allow it in the access key ID field, while still refusing a secret access key pasted anywhere. Note the difference in the guard's tests.
- Last-used comes per key from GetAccessKeyLastUsed. One call per key, so mind the request rate on large accounts.
- Real check: read the staging account (`--profile staging`) locally.
