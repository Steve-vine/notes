Sprint "Secrets - New Module" (ADR 0141, COM-1563). Builds on COM-1564.

## What people see

- **Admin ▸ Rubrics ▸ Secret rotation intervals.** One row per kind of secret, each with an interval in days or "No schedule".
  - Defaults: API key, deploy key, client secret, password and other: 365; access key and token: 90; certificate: No schedule, because its expiry drives it.
  - Editing it needs the usual rubric permission. Changes are logged.
- **Per secret:** "Rotate every" follows the rubric unless it's changed on the secret, with a reason. The page shows which applies ("Every 90 days — the rubric for access keys").
- **Next due** = the earlier of:
  - the expiry;
  - the last rotation plus the interval (or the date it was created, if it has never been rotated).

  With neither date known, it shows **"Needs a date"**: never due, and filterable, so someone can fill it in.
- **On the secret and in the register:**
  - **Age**, from the last rotation, or from its creation if never rotated (e.g. "2 y 4 m").
  - **Expires**.
  - **Last rotated**.
  - **Next due**, with a state pill: *Due in 12 days*, *Overdue by 5 days*, *Expired*.
- **Long-lived.** A secret marked "Doesn't expire" (or whose source says it never expires, in later tasks) gets a **Long-lived** pill. It sorts by age, and there's a **Long-lived** filter.
  - The pill **raises nothing**: no action, no gap, no check failure (Steve, 2026-11-03).
  - A long-lived secret is still due when its rotation interval comes round, like any other.
- **Figures** above the register: Overdue · Due in 30 days · Long-lived · Needs a date. Each one filters the register.
- Retired secrets are never due.

## Notes (technical)

- The rubric is a new reference table seeded with the defaults: migration plus seed. Seed data repairs belong in the importer, not a migration (memory: seed import runs every deploy). Show it under Admin ▸ Rubrics like the vulnerability fix-by targets (ADR 0129).
- Compute next due on read in one function (`core/secrets/due.py`), not stored, so a rubric change applies at once. Expose `next_due`, `due_state`, `long_lived`, `age_days` on the API.
- Dates are company time zone days (ADR 0121).
