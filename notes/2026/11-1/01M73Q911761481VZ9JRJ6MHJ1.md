The Vulnerabilities side of ADR 0145 (COM-1695), plugged into feeds (COM-1697).

**Chain:** on the chain — migration + API

## What the person sees

- A feed into Vulnerabilities is a **source** like Nessus or Aikido. Sightings, the Latest reads list, filters and history name it after the Collection integration (e.g. "GitHub"), with its logo.
- Its findings follow ADR 0129's amendment exactly:
  - **targets** (a repository, image, host, URL or resource) are placed by what Compass already knows, then by matching rules (which can be limited to this source), then on **Unmatched**;
  - the same CVE on the same system from two sources is one vulnerability with two sightings;
  - a finding with no CVE is the source's own check (`check:<integration>:<rule>`), where `<integration>` is the integration's own stable key, not a name in code.
- **Closing**, as the feed declares:
  - *the source says so*: the mapped status reads solved, so the finding closes; it reads open again, so the vulnerability reopens as the same VUL;
  - *missing from a complete read*: a finding not seen again closes, but only for targets the read covered.
- **Accepted in the source:** a status mapped to *accepted* comes in as **Accepted by <service>**, with the service's reason and end date where mapped. Once the end date passes it's open again. Same as Aikido today (ADR 0129 §4a).
- **Severity** comes through the feed's value map, or the CVSS score when mapped. Fix-by dates come from the company's settings as for any source.
- Text from the service is untrusted, shown as the service's words, and returned by Polaris under `from_the_source`.
- One account belongs to one company. That account's findings go to its company. (Several companies per account is sprint sj4f1kj.)

## Done when

- A feed can map every slot in ADR 0145's Vulnerabilities shape. The preview shows the vulnerabilities and Unmatched targets it would create.
- Placing, rules, Unmatched, merging with other sources, closing, reopening and accepting behave as for Aikido, tested against real Postgres with a fake service.
- `vulnerabilities_latest_reads` and the Latest reads screen show feed reads, with their counts.
- A source's feed switched off or deleted stops new sightings. Existing vulnerabilities stay, and nothing closes because the feed stopped.
- No service name in code (COM-1696).

- `models/vulnerability_source.py`: a feed source is identified by the integration, not by a new enum value per service. Check `TargetKind` and the sources list in `core/vulnerabilities/sources.py`.
- Reuse `core/vulnerabilities/matching.py` and `lifecycle.py`. The Aikido reader (`aikido_read.py`) is the model to follow, but don't copy its Aikido-specific parts.
