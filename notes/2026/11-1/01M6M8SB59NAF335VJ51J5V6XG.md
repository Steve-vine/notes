Adding a control to an initiative brings in **all** of its gaps, including ones already closed. In Test Company, adding INS.1 to INI-3 "Control review" brought in G-10, completed on 31 Oct, days before the initiative. It counts as finished work, so INI-3 showed 5% (1 of 20) with nothing done in it.

Steve first noticed that INS.1's Open gaps column read "—" while G-10 was on the initiative. That was correct, since G-10 is closed. The problem is that G-10 joined at all.

**Steve (2026-11-04): leave them out.** Progress measures work done during the initiative.

**Wanted behaviour:**
- A gap joins the initiative through its control if it's still open when the control is added, or is raised afterwards.
- A gap that closes while the control is on the initiative stays and counts as done.
- A gap closed before the control was added doesn't appear and doesn't count. If it's reopened later, it joins.
- *Assumption (decided, not asked): the same rule applies to risks brought in by a control. A risk already closed before the control was added stays out, so its treatment doesn't count as done.*
- Adding a gap directly still works for any gap. Choosing it is deliberate.
- Finished initiatives keep their snapshot unchanged.

**Done when:** in E2E Test Company, start an initiative and add a control that has one completed gap and one open gap. The initiative shows only the open gap, at 0%. Completing that gap moves it to done. Reopening the old completed gap brings it in as open. INI-3 in Test Company no longer lists G-10 and doesn't count it.

**Implementation:** the live resolver `core/initiatives/members.py` (~L153) selects every non-deleted gap on the initiative's controls. Add `Gap.closed_at IS NULL OR Gap.closed_at >= <that control's added_at>`. The control's `added_at` is already available via `source(control_id)`. Do the same for risks if `Risk` has a closed timestamp. If it doesn't, compare against status history, or note what was done in the PR. `progress.py` and the Open gaps column then follow automatically. Add integration tests for closed-before, closed-during and reopened, and the risk equivalent.

**Independent:** no migration expected, and the API shape doesn't change.
