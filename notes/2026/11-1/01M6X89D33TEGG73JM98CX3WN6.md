Steve (2026-11-08): administrators see all connections.

**Wanted behaviour:**
- A list on the Admin page of every connected assistant across Compass: the person, the assistant's name, connected on and last used. It can be sorted and filtered by person and assistant.
- During the switch-over the list also shows **personal tokens still being used by an assistant**, marked as such, with who and when last used. This is how an administrator knows when it's safe to end the switch-over.
- An administrator can disconnect any connection (and, for an old token, stop it working for assistants) after confirming. It ends at once. The person sees it gone from their Connect page. Recorded in Activity as done by the administrator.
- Visible only to people who can manage users and tokens today. Same audience as the existing token list on Admin.

**Done when:** in E2E Test Company, with two test accounts each connecting a local Claude Code, the admin account sees both with last-used times and disconnects one, which is refused on its next call, while the other carries on. An account without the admin right can't see the list or call its API.

**Implementation:** list and disconnect API under `/api/v1` (admin-scoped, same permission as the token list), plus a table on the Admin page with `SortableTh` (screen-conventions test). "Token used by an assistant" needs the gate to record when a personal token last opened `/api/mcp`. Store that per token (a column on the token or a small table) in this task, or in COM-1642 if that lands first. Polaris-window credentials are not listed.

**On the chain:** API (and a migration for the per-token "last used by an assistant" field).
