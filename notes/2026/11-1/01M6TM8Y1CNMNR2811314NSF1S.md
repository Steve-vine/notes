Raised by Steve while testing on staging (2026-11-07). Polaris found no logo when defining GitHub, so the tile shows a letter, yet the Core GitHub integration has an icon.

## Why

- The Core tiles' marks ship inside the app: vendor artwork in `app/frontend/src/integrations/logos/` (see `SOURCES.md`), plus GitHub, Microsoft and SMTP from the Phosphor icon set (`IntegrationLogo.tsx`). Polaris can't see any of them.
- Polaris looks for a logo only among the images linked from the API docs pages it reads (at most 8). It takes one only if it "saw it linked". API docs rarely link the brand mark, so most services will come back without one.

## Done when

1. **Compass's own marks first.** When the service matches one Compass already has (GitHub, Microsoft or Entra, AWS and its services, Azure, Google Cloud, SendGrid, Tenable, Aikido…), the review step offers that mark: "Use Compass's GitHub logo". The match is on the service name or the base address host, and the person can still say no. This works without Polaris finding anything. The mark comes with its light/dark variant where Compass has one, and the integration keeps its own copy as now.
2. **Otherwise the service's own brand page.** Polaris is told to look for a press, brand or logos page (e.g. github.com/logos, a "press kit", "brand assets") as one of the pages it reads, and to prefer the symbol on its own over a wordmark, as SVG or PNG.
3. **Last resort: the site's icon.** Compass tries the service's own apple-touch-icon or favicon from its main site (not the API host). It says so, "Compass used the icon from github.com", and lets the person decline.
- Only https, only from the service's own domains. It is fetched once at save and kept by Compass (as now). Nothing is loaded from a vendor at run time.
- Still a letter if all three find nothing, with "You can upload one later" as now.
- Tests: GitHub matches Compass's mark by name and by host (api.github.com); an unknown service with no brand page falls back to its site icon; a logo on another domain is refused.
- On staging: re-defining GitHub offers the GitHub mark. Defining MongoDB Atlas gets a logo from its brand page or site icon.

## Where

- `core/collection/polaris_define.py`: DEFINE_SYSTEM (the brand-page hint) and `logo_url`.
- `api/v1/collection_integrations.py` `_from_proposal`: the logo is kept here; add the own-mark match and the site-icon fallback.
- `integrations/collection/WithPolarisPage.tsx`: the logo checkbox text.
- The bundled marks: `integrations/logos/` and `IntegrationLogo.tsx`. The backend needs a copy or a list of these to offer them.
