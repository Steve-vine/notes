**Why.** Rule 1 (COM-1682): there must be no doubt that a criterion is met when its controls are. Some points of focus have no control that carries them. Likely ones so far:
- telling people when the privacy notice changes (P1.1);
- periodically reviewing who can enter secure areas (CC6.4).

The full list comes from COM-1689.

**What changes:**
- **New controls.** Add the new controls Steve agreed in COM-1689 to the library, each with a reference, wording and tier, as COM-1670 did. Link each one to SOC 2 and to every other framework it plainly serves.
- **Wording changes.** Where Steve chose to reword an existing control instead, record the change in the task's PR so its effect on other frameworks is visible. The wording on an environment that has already imported the control isn't overwritten: the import only adds missing controls. So a reworded control is changed on screen on staging and production, or it becomes a new control and the old one is retired. Decide which per control and say so in the PR.

**Where.** `data/controls.csv` and the mapping CSVs, plus their tests. Data only. **Independent.** Blocked by COM-1689. Skip this task if COM-1689 finds no gaps.

- Every gap in the signed-off set has its control in the library.
