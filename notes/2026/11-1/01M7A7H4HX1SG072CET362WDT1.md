## Why

Steve, testing on 2026-11-13: on the SAP **Timeline**, completed access recertifications aren't ticked as done the way plan entries are.

## What's wrong

The other reviews Compass shows beside the plan (COM-1048) are access recertifications, asset recertifications and content reviews. Compass already knows each one's state: Scheduled, Under way or Completed. But the views draw every one of them the same way, as a grey dashed bar, so the state only appears in the hover text.

- `app/frontend/src/sap/SapTimeline.tsx`, around line 220: the extra-item bar renders no `CheckIcon`.
  - Plan entries do render it, at line 212.
- `app/frontend/src/sap/SapCalendar.tsx`, around line 171: the same applies to the calendar chip.
- `app/frontend/src/sap/viewStyle.ts`:
  - `ExtraItem` doesn't carry the status;
  - `extraStyle` is a single fixed style.
- The backend is fine. `core/sap_other_reviews.py` already returns `status: completed` when the period's run has `completed_at` set.

## What changes

- A **completed** access or asset recertification shows the same small tick as a done plan entry, on both the Timeline and the Calendar.
- It stays neutral grey with a dashed edge, so it still never reads as a plan entry. Make the grey solid when it's completed, matching how a done plan entry goes solid in its own colour.
- **Scheduled** and **Under way** recertifications look as they do today. Content reviews ("Review due") are unchanged.
- The hover text is unchanged.

## Independent

Frontend only. No API change and no migration.

## Done when

- On staging, E2E Test Company has an access recertification whose run is completed. On the SAP Timeline it shows a tick and a solid grey bar.
- It shows the same on the Calendar.
- A scheduled or under-way recertification has no tick.
- An asset recertification behaves the same.
- Tests in `SapViews.test.tsx` cover a completed and a scheduled other review.
