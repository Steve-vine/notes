Sprint 100, Actions. Found by Steve on staging, 1 Nov 2026. Introduced by COM-1470, which gave each action a Type and an Action.

## What happens

On Actions, the Type chips include both **Vulnerabilities: 1** and **Vulnerability: 5,364**. Every vulnerability action is typed "Vulnerability" except "Place unmatched findings", which is typed "Vulnerabilities". Chips group by Type, so the module splits in two. The same happens in the Type filter and anywhere Polaris lists actions by type.

I checked every other action type: this is the only mismatch.

## Fix

- "Place unmatched findings" is typed **Vulnerability**, like the rest of the module. Actions then shows one Vulnerability chip that counts all of them.
- A test fails if one action type's Type is the plural of another's, so a module can't split like this again.

**Chain:** independent (a label, no migration or API shape change).

**Done when:**
- Actions shows a single Vulnerability chip, whose count includes the unmatched-findings row.
- The new test passes.
