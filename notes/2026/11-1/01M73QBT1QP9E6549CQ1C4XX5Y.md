The decision for sprint "Collection integrations - more applications". Steve, 2026-11-10: make Collection integrations able to work with many more applications, using GitHub, Aikido and Nessus as the first targets. All logic lives in the configuration, and "if integration = GitHub, always do this" is a hard no (ADR 0145, COM-1695).

**Chain:** independent (an ADR)

## What it decides

Each item is a general capability. Its first user is named only to explain why it's needed.

1. **Follow-on reads.** Read a list, then read each item at an address built from that item's fields, nested up to three levels deep. Lookups are de-duplicated (the same address is read once per run), there's a cap on how many follow-on reads one run may make, and "no permission" on one item is handled as declared (skip it and leave its records as they were, or break). First users: per-repository deploy keys and Actions secrets; Nessus hosts.
2. **App sign-in.** A private key signs a short-lived token, which is exchanged at a stated address for an access token, optionally after a lookup step (e.g. finding the installation). Everything is declared: the claims, the algorithm, the addresses and where the token is in the answer. The private key is write-only (ADR 0141 §2). First user: a GitHub App.
3. **One account, several companies.** A feed names the field that identifies a *part* (a repository, container, cloud or scan). Parts are listed on the integration and each is assigned to a company or set to Don't read. New parts are Not assigned and turn the tile to Needs attention (ADR 0129 §3a, made general). First users: Aikido and Nessus.
4. **Limits per read.** A read's own timeout, item and size caps (within hard ceilings Compass sets), and one retry on a timeout. First user: Aikido's issues download (COM-1693).
5. **Incremental reads.** A read can ask for only what changed since the last successful run. A feed reading incrementally may only close records the source says are closed, never by "missing".
6. **Choosing which run to read.** Filter a list and take the newest by a field (e.g. the latest finished run of each scan), then pass its ID on to the next read.
7. **Closing only where it looked.** A feed names the scope field (e.g. the hosts in that run), and "missing" closes only within that scope. A host missing from a run closes nothing.
8. **Named internal addresses.** *This is for Steve to decide (see the comment).* Today a Collection integration may reach public addresses only. Proposed:
   - an administrator keeps a list of approved internal addresses (host and port), under a right separate from defining services;
   - a service may use only an address on that list;
   - the cloud metadata service, link-local and loopback addresses, and Compass's own cluster and database ranges are refused whatever the list says;
   - a service can carry its own CA certificate.
   
   First user: Nessus Expert on the internal network.

What stays out: anything but reads (Nessus's "prepare an export" is deliberately not allowed, because the JSON reads give the same data), non-JSON answers, and running code.
