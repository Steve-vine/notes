Found 2026-09-30 while opening the sprint 65 PRs (#805, #806; run 36765077914). `pip-audit (backend)` in the required `deps-scan` check now reports **urllib3 2.7.0: CVE-2026-97687, CVE-2026-97688 and CVE-2026-97689, all fixed in 2.8.0**. Nothing merges until it's fixed, whatever the PR touches.

## What changes

Nothing visible. The HTTP library Compass's backend uses under the hood (through requests, Graph and storage clients) moves to the fixed version.

## Notes (technical)

- urllib3 is **transitive**: `pyproject.toml` doesn't name it. `uv lock --upgrade-package urllib3` moves the lock. Add a `[tool.uv] constraint-dependencies = ["urllib3>=2.8.0"]` floor so a fresh resolve can't fall back to a vulnerable version.
- Run the backend unit tests and the HTTP-client integration tests against the new version.

**Done when:** `deps-scan` is green on main, and the sprint 65 PRs (#805, #806, #807) rebased onto it pass.
