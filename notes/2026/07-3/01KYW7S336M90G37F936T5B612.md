The delivery half: from a pending `notification_delivery` row to a card in a Teams channel.

- Adaptive Card renderer per event type: severity accent colour, incident/action title, affected entity + system, deep link back to the ISE screen (needs a public base-URL setting if none exists).
- Teams poster: POST the card to the channel's Workflows URL over an httpx client behind a `build_client()` seam (status_pages.py pattern — the monkeypatchable seam contract tests use).
- `deliver_notification` Celery task (one delivery row per invocation, one session per item) + Beat `dispatch-pending-notifications` sweep mirroring `dispatch_approved_changes` (execute.py): the emit point enqueues immediately AND the sweep re-selects anything still pending/failed under the attempt cap — a broker blip cannot silently drop a notification. Bounded attempts with backoff via the sweep; terminal failures marked `failed` with last_error.
- Per-incident anti-flap guard: suppress a duplicate opened/reactivated notice for the same incident within the configured window.
- POST test-send endpoint per channel (renders a sample card, records a delivery row).
