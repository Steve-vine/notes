So that the UI looks and behaves the same on the three WebView engines — macOS WebKit, WebKitGTK (Linux) and WebView2/Chromium (Windows). The frontend is ~45k lines and only one line is platform-aware (`TabStrip.svelte` `isMac`), which is the good news; the editor (`livePreview.ts`, `Editor.svelte`) has only ever been exercised on one engine, which is the risk.

**Draft — re-plan after NOT-498 reports. Needs Steve's eyes on a Linux and a Windows machine — screen capture isn't available to Claude.**

## Proposed work

- [ ] Window chrome: `titleBarStyle: Overlay` / `hiddenTitle` / `trafficLightPosition` are macOS-only. Windows and Linux get native decorations; the rail and tab strip lay out without the traffic-light inset (the existing `isMac` branch) — check nothing else assumed the inset.
- [ ] Attachment URLs: `convertFileSrc` yields `http://notuvia-attachment.localhost/…` on Windows, not `notuvia-attachment://localhost/…`. Audit for anything that parses or pattern-matches the URL shape; fix `markdown.test.ts`'s "macOS custom-scheme shape" stand-in to cover both.
- [ ] Printing: `print_webview` already falls back to `window.print()` off macOS — confirm the staged document (ADR 0062) prints acceptably on both.
- [ ] Spell-check: the WebKit text-checking seed is macOS-only; check WebView2's built-in spell-check and WebKitGTK's behaviour, and that autocorrect-style substitutions are off.
- [ ] Editor pass: contenteditable selection, caret, IME, paste, drag-resize of images, keyboard shortcuts (`Ctrl` for `Cmd` is already in place) on each engine. Capture findings as follow-ups rather than widening this brief.
- [ ] Fonts: `ui-monospace, SFMono-Regular, Menlo, monospace` and `var(--font)` — confirm sensible fallbacks land on each OS.
- [ ] Scrollbars and focus rings: Chromium and GTK draw these differently; align where it matters.

## Notes

Linux first is the cheaper order technically (WebKitGTK is WebKit; the Rust side already compiles on Linux), but the public roadmap puts the Windows beta before Linux — decide the order when planning from NOT-498's results.
