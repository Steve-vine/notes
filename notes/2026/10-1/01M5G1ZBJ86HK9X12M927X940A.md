Sprint 82, Evidence (ADR in COM-1198). Builds on COM-1199. COM-1200 uses it: every piece of evidence is filed under one of these types. Steve asked for this rubric on 2026-10-21; the defaults below are the ones he approved.

**Chain:** on the chain — migration + API

## What people see

**Admin ▸ Rubrics ▸ Evidence types**, after the Incident rubric. It is organisation-wide: one list for every company.

**Default types:**

| Type | Description (shown as a hint when choosing) | Valid for |
|---|---|---|
| Policy or procedure | A governance document: policy, standard, procedure or runbook | 12 months |
| Configuration or screenshot | How something is set up, captured from the system | 12 months |
| Report or export | Output from a tool or system: a scan report, an access list, a dashboard export | 12 months |
| Log or record | A record that something happened: a ticket, a log extract, minutes, a sign-off | 12 months |
| Certificate or audit report | An external certificate or attestation: ISO, SOC 2, Cyber Essentials, an auditor's report | 12 months |
| Test result | The outcome of a test: a pen test, a restore test, a DR exercise, a phishing simulation | 12 months |
| Other | Anything that doesn't fit the above | 12 months |

**What an admin can do:**
- **Add** a type: a name, a description and a validity in months.
- **Rename** a type or change its description. Evidence filed under it follows the new name.
- **Reorder** the types; the order is the order of the pick-list.
- **Valid for**: how long evidence of this type stays current when nobody gives it a valid-until date. Out-of-date warnings (COM-1210) use it. Every type starts at 12 months. *(My call: a certificate typically runs three years, but the defaults stay uniform and admins change them.)*
- **Retire** a type that's in use. Evidence already filed under it keeps it, shown as "(retired)", but it can't be chosen for new evidence. It can be brought back.
- **Delete** a type that no evidence has ever carried. A type in use says "retire it instead".
- **Other** can be renamed but never retired or deleted, so evidence always has somewhere to go. *(My call.)*
- Every change is kept, with who changed it and when, like the other rubrics' history.

**Who can change it:** Manage rubrics, as for the other rubrics. Anyone who adds evidence sees the types in the pick-list.

## Notes (technical)

- An `evidence_types` table: name, description, `valid_months`, position, retired_at, plus a revisions table. Seeded in the migration with the seven above. Audited.
- Modelled on the incident categories (`api/v1/incident_rubric.py`: 409 on deleting a type in use, retire instead), with a guard on Other (a fixed key).
- The section is added to the `RUBRICS` list in `pages/AdminPage.tsx`.

**Done when:**
- the seven defaults appear in Admin ▸ Rubrics;
- an admin can add, rename, reorder and retire a type;
- deleting a type in use is refused;
