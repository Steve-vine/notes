Part of sprint 67, Inventory discovery - Software (ADR 0114, follow-up to COM-966/967/968). Raised after the first real read on staging, 2026-10-18.

## Why

A Linux server's agent reports every package on it. On the Staging AWS account, the 17 servers reported 11,853 entries, 1,602 of them different, and over 95% were the operating system's own packages (`bash`, `audit-libs`, `cloud-init`, kernel modules). Publishers were "Amazon Linux" (853) and "Ubuntu Developers" (603), followed by Ubuntu and Canonical kernel teams. Shown as they are, these swamp the software someone actually chose to install. Without them, the list drops to roughly 100.

## What people see

- **Discovered ▸ Software has a filter "Hide operating-system packages", on by default.** With it on, packages that ship as part of a server's Linux distribution are not listed. What's left includes the operating system itself (Amazon Linux 2023, Ubuntu 24.04), runtimes and databases Compass recognises, and anything added on top: NVIDIA drivers, the SSM agent, vendor agents, applications.
- **Turning it off shows everything,** as today. The choice is kept in the address like the view's other filters, so it can be shared.
- **Nothing is thrown away.** The packages are still read and kept; the filter only hides them. Discarding works as before.
- **Counts follow the filter.** "on N technology assets" and the view's total reflect what's shown. A note says how many operating-system packages are hidden ("1,480 operating-system packages hidden"), so it's plain they exist.
- **The same applies to every cloud:** AWS Systems Manager, Azure Change Tracking and Google VM Manager.
- **Windows is unaffected.** Its list is already applications only, with updates left out.

## Notes (technical)

- Mark each agent-reported row as an OS package when it is read (a flag on `discovered_software`, set in `core/discovery/installed.py`), rather than working it out at query time. This needs a new migration and a backfill on the next read, with no hand-editing of 0274/0275.
- Deciding "OS package": the publisher matches the server's own distribution: Amazon Linux, Ubuntu Developers / Ubuntu Kernel Team / Canonical Kernel Team / Ubuntu Core Developers, Red Hat, Debian, SUSE, CentOS, Rocky, AlmaLinux, Oracle Linux. Match case-insensitively, as a table next to `os_names.py`.
  - Ubuntu/Debian packages often carry an individual maintainer as publisher (e.g. "Mathieu Trudel-Lapierre", "Michael Vogt", "Steve Langasek"). Check whether the SSM / Change Tracking / OS Config entry gives a better signal: SSM `AWS:Application` has `PackageId`, `URL` and `Release` (e.g. `0ubuntu1`, `amzn2023`). A release/version suffix naming the distribution is likely more reliable than the publisher. Choose, and say which in the PR.
- Never hide rows Compass keys as a known product (`runtime:`, `os:`, engines). An OS-supplied Python is still a runtime row, so it stays visible.
- Filter param on `/inventory/discovered/software` (default on), wired through `discoveredSoftwareHooks.ts` and the URL-backed filter state (`?…` alongside sq/stype/sin/dated/found); regenerate `schema.d.ts`.
- Tests: a fake Amazon Linux and Ubuntu package list (including maintainer-named publishers) where only non-distribution packages survive with the filter on; all of them return with it off; and the hidden count is right.

**Done when:** on staging, Discovered ▸ Software for servers on the Staging AWS account shows about a hundred entries by default, rather than 1,600, with the hidden count shown, and turning the filter off brings the rest back.
