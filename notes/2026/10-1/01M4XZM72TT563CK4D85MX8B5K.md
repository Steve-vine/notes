Part of sprint 67, Inventory discovery - Software (ADR in COM-959). The Google counterpart of COM-966. It looks the same on screen, and nothing is installed or logged into.

## What people see

- **For each Google Cloud server under a technology asset that reports an OS inventory,** its installed software appears in Discovered ▸ Software, grouped with the same software elsewhere. Its operating system becomes *reported by the server* (COM-964).
- **Updates and hotfixes are left out.**
- **A server that doesn't report** says "Installed software: not reported. Switch on VM Manager to see it". The project card says how many servers report.

## Notes (technical)

- OS Config API v1: `projects/{p}/locations/{zone}/instances/-/inventories?view=FULL`. Use `osInfo` (longName, shortName, version) and `items` where `type=INSTALLED_PACKAGE`. Package kinds: `yumPackage`, `aptPackage`, `zypperPackage`, `googetPackage`, `cosPackage` and `windowsApplication` are read; `wuaPackage` (Windows Update) and `qfePackage` (hotfixes) are not, which satisfies "all but updates".
- Every request names `fields` (the `core/gcp.py` rule). Permission `osconfig.inventories.list` goes into the generated custom role (`core/gcp_role.py` → `docs/gcp/`). Note in the docs that the OS Config agent and VM Manager must be enabled on the project.
- Zones come from the instances already read, so avoid a `locations/-` wildcard unless it is confirmed to work. That form has not been proven against a real project yet (see the GCP sprint).
- Fakes in `tests/gcp_fakes.py`.

**Done when:** a faked project's reporting instance shows its packages with no Windows updates, and a non-reporting one shows "not reported". On staging, only if Steve has a Google project with VM Manager on; otherwise the task says so.
