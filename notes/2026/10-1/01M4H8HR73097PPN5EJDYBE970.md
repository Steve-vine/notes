Raised by Steve on staging, 2026-10-09 (`b2e4240a`): "While it shouldn't be possible to remove or change dynamic groups, it should display a popup describing it when clicking on it like other groups."

## What people see today

On a move, **Dynamic groups (n)** is a row of plain names. Role groups and manual groups open a popup when clicked; dynamic groups do nothing.

## What people should see

- Clicking a dynamic group opens the same kind of popup as the other groups: its name, its description (or "This group has no description."), and a line saying why they are in it — a rule decides who is in this group, so it can't be added or removed here.
- **No Remove**, and nothing else that changes it — as for role groups.
- If Compass knows the rule, show it in the popup; if it doesn't, the popup simply doesn't mention it. (Decide from what the mirror holds — don't add a directory read for this.)
- The heading and the sentence under it stay as they are, with "select one to see what it is" added, to match the other sections.

## How (implementation)

- `app/frontend/src/access/MoverStayingGroups.tsx`: the dynamic section (~l.360) renders bare `<Badge>`s. Role groups already have a read-only popover (`rolePill`) and manual groups a full one (`pill`) — give dynamic groups the read-only one, with its own "why" line instead of `whyHeld`'s role text. One popover open at a time, shared `opened` state, as now. Accessible name `"<group> — details"` like the others.
- Rule text: check whether the mirror carries the membership rule for a dynamic group (`DirectoryGroup`; `membership_type === 'dynamic'` is what the form reads today) and whether `DirectoryUserGroup` already exposes it. If it is not in the API response, **leave the rule out** rather than widen the read — note it on this task.
- Screen conventions: a pill never truncates (`brief/information-architecture.md`).
- Test in `MoverStayingGroups`'s tests (or `MoverRoles.test.tsx`, where the staying-groups cases live): clicking a dynamic group shows its description and no Remove button. Popovers in jsdom: see the Mantine Menu/jsdom memory.
- Frontend only unless the rule needs exposing. No migration.

## Done when

- [ ] A dynamic group on the move form opens a popup with name, description and the "a rule decides" line.
- [ ] There is no Remove or any other control in it.
- [ ] Role and manual group popups are unchanged.
