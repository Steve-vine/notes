Found in Steve's smoke test of sprint 71 (COM-989 / COM-990), 2026-10-16: "the Document Review page is always generated in A4, even when the house style is set to letter."

## What is wrong

A templated document's PDF (Print preview, the PDF export, and bulk export) ends with a **Document Review** page listing its reviews. That page isn't made with the rest of the document. It's drawn separately, by the older report renderer, and stapled on afterwards. So it:
- is **always A4**, with its own fixed margins, even when the house style says Letter;
- uses **Helvetica**, not the style's fonts;
- has **no header or footer**, so the page numbers stop before it.

The Word export is right already: its review section is part of the document, in the style's page size.

## What people see

- **The Document Review page is the last page of the document itself:**
  - the house style's page size (A4 or Letter) and margins;
  - its fonts and text colour;
  - its header and footer, with page numbers that count it, so "Page 6 of 6" really is the last page.
- **The page keeps its plain look:** the title "Document Review", the document's name, then one row per review (Reviewed, Reviewer, Job title, Comment), newest first, with a header row. It uses the style's own table rules (borders, header shading), so it matches the document's other tables. A long history still runs over several pages, with the header row repeated.
- **No reviews yet:** it says "No reviews recorded yet." as now.
- **Documents kept in SharePoint** (managed content, which Microsoft renders) still get their review page added at the end. It now takes the size of the document's own last page rather than always being A4.
- **Previews:** the house style's live preview shows the review page the same way, with the sample's reviewer, so the designer can see it.

## Technical

- **Cause:** `tasks/pdf.py:222` calls `_with_review_record()`, which renders `core/review_pdf.py` `render_review_record()` (ReportLab, `pagesize=A4`, 18 mm margins, Helvetica) and appends it with pypdf.
- **Templated documents:**
  - drop the append, and render the review record in the WeasyPrint HTML as the document's final block (`core/render/document.py`): a `<section class="rt-review">` with `break-before: page` and a `table.rt-table` whose `<thead>` repeats across pages;
  - the rows are the same `review_rows` the Word and text exports already get (`_ensure_styled_pdf` builds them), so all three formats share one source;
  - the header and footer bands apply because it's the same document; check `counter(pages)` includes it.
- **Style preview** (`generate_style_preview`, `core/render/sample.py`): give the sample one review row, and have COM-996's dates match it.
- **Managed content:** `_ensure_managed_pdf` (≈440–465) keeps `render_review_record`, but pass the page size of the last page of Microsoft's PDF: pypdf `mediabox` → points → ReportLab `pagesize`. A4 stays the fallback.
- **Bump `_STYLE_RENDERER_VERSION`** so cached PDFs re-render.
- **Tests:**
  - Python: a Letter style's PDF has every page, including the last, at 612 × 792 pt (pypdf);
  - the last page's text contains "Document Review" and the footer's page number;
  - no `review_pdf` import on the styled path;
  - a managed PDF with Letter pages gets a Letter review page.
