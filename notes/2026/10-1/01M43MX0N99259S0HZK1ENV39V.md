So that Notuvia is usable on a clean Windows install — found by the first hands-on pass of the 0.32.0 NSIS build on a Windows VM (2026-10-04).

## Agreed work

- [x] Creating a window never happens on the event-loop thread (ADR 0069, amends ADR 0033). On Windows, building a WebView2 window from a sync command or a hotkey/tray handler deadlocks: the Browse tab's New note button opened a blank window and froze the app; the capture hotkey froze it the second time the window had to be built. `open_capture_window` and `open_note_window` now build on a spawned thread — one path for button, hotkey, tray, Kanban "+" and note pop-out.
- [x] `notuvia-mcp.exe` links the VC++ runtime statically (build.rs + `static_vcruntime`), as tauri-build does for the app. A clean install raised "VCRUNTIME140.dll was not found" at startup and on opening Settings, where the app runs `notuvia-mcp --version`.
- [ ] Verified on the Windows VM from the post-merge CI installer.
