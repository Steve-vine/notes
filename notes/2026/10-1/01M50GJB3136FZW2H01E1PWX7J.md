Sprint 71, Improve templated content (ADR in COM-986). This is the foundation the editor, the renderer and the exports build on.

## What people see

- **Nothing changes on screen yet.** Every templated document reads and exports as it does today.
- Behind the scenes, each section now holds rich content, in the format the new editor writes. Every document and every past version converts, keeping:
  - headings, lists, bold and italic;
  - links, tables and code.
  Anything the converter doesn't recognise is kept as plain text, never dropped.
- Search finds the same words, and version history still shows the differences between two versions.
- The assistant (COM-978) keeps reading and writing sections in Markdown, and Compass converts in both directions. A fenced `mermaid` block becomes a text diagram once COM-994 lands.

## Notes (technical)

- `content_sections` gains `doc` (JSONB, ProseMirror JSON with a schema version). `body` stays as a derived Markdown/plain-text rendering, so the rollup, FTS and the version diff are unchanged. `content_versions.sections_json` entries gain `doc` too, and the migration converts them.
- **Define the node and mark set once**, in a shared schema the Python converter and the Tiptap editor are both tested against: paragraph, heading 1–6, bullet and ordered list, blockquote, code block, horizontal rule, table (header row, colspan/rowspan), hard break, link, bold, italic, underline, strike, code. Leave room for callout, page break, image, diagram and the contents/posture/domain-controls blocks; COM-988, COM-992, COM-993 and COM-994 add those.
- Markdown to doc uses markdown-it-py (already a dependency); doc to Markdown is a small serialiser. Round-trip test every seeded document.
- The API takes either `doc` or `markdown` when writing a section and returns both. Run the OpenAPI drift script.
- The Word-template path keeps working from the derived Markdown until COM-995 retires it. `placeholder` stays for now, and new sections get a generated one.
- Migration test: raw SQL on a populated database (memories: migration-tests-orm-fixtures-drift, migrations-fresh-db-blindspot).

**Done when:** on staging, every templated document reads and exports as before, search and history behave the same, and an edit made through the assistant lands as rich content.
