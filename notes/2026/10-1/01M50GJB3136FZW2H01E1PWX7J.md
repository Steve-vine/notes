Sprint 71, Improve templated content (ADR in COM-986). This is the foundation the editor, the renderer and the exports build on.

## What people see

- **Nothing changes on screen yet.** Every templated document reads and exports as it does today.
- Behind the scenes, each section now holds rich content, in the format the new editor writes. Every document and every past version converts, keeping:
  - headings, lists, bold and italic;
  - links, tables and code.
  Anything the converter doesn't recognise is kept as plain text, never dropped.
- Search finds the same words, and version history still shows the differences between two versions.
- The assistant (COM-978) keeps reading and writing sections in Markdown, and Compass converts in both directions. A fenced `mermaid` block becomes a text diagram once COM-994 lands.

## Markdown that loses nothing (Steve, 2026-10-15)

Compass's Markdown can say everything the rich editor can. That makes two things safe:

- the editor's **Rich text | Markdown** switch (COM-988);
- the assistant editing a section: it can't flatten a merged table or drop a callout.

Going rich → Markdown → rich gives back exactly what you started with. The Markdown is plain where Markdown has a form, and extended where it doesn't:

| In the editor | In Markdown |
|---|---|
| Headings, lists, bold, italic, links, code, quotes, simple tables | Standard Markdown (GitHub-flavoured) |
| Underline, strikethrough | `<u>…</u>`, `~~…~~` |
| Callout | `> [!NOTE]`, `> [!WARNING]`, `> [!IMPORTANT]` (GitHub's alert syntax) |
| Page break | `{{page-break}}` on its own line |
| Contents, Posture, Domain controls | `{{contents}}`, `{{posture}}`, `{{domain-controls}}` on their own line |
| Text diagram | a ```` ```mermaid ```` block |
| Image or drawn diagram | `![caption](compass:image/<id>){width=50% align=center}`, `![caption](compass:drawing/<id>)`. They can be moved or deleted in Markdown. The picture itself is changed in rich text. |
| A table Markdown can't express (merged cells, shading, column widths) | a small HTML `<table>` block |
| Text colour | `<span data-colour="accent">…</span>` (style-palette names only) |

**Double braces, not square brackets** (Steve, 2026-10-15). Square brackets get confused with ordinary text, so the special blocks are written `{{…}}`. A literal `{{` in prose is written `\{{`. The Word templates keep their `[…]` placeholders until COM-995 retires them. They aren't worth changing on the way out.

## Notes (technical)

- `content_sections` gains `doc` (JSONB, ProseMirror JSON with a schema version). `body` stays as the derived Markdown (the lossless form above), so the rollup, FTS and the version diff are unchanged. `content_versions.sections_json` entries gain `doc` too, and the migration converts them.
- **Define the node and mark set once**, in a shared schema the Python converter and the Tiptap editor are both tested against: paragraph, heading 1–6, bullet and ordered list, blockquote, code block, horizontal rule, table (header row, colspan/rowspan), hard break, link, bold, italic, underline, strike, code. Leave room for callout, page break, image, diagram and the special blocks; COM-988, COM-992, COM-993 and COM-994 add those.
- **Converters, both ways, in Python** (markdown-it-py for parsing, a serialiser for writing). The browser needs the same pair for the switch. Either:
  - port them to TypeScript against the same schema, with a **shared fixture set both suites must pass**; or
  - have the editor call a small convert endpoint.
  Choose in the PR. A shared fixture set is mandatory either way.
- The round-trip property is a test: for every fixture and every seeded document, `doc → md → doc` is identical. `md → doc → md` is identical after normalisation (list markers, spacing).
- HTML in Markdown is accepted **only** in the forms in the table: `<u>`, `<span data-colour>`, and `<table>` with `colspan`/`rowspan`/`data-*`. Anything else is escaped as text, never rendered. This is a sanitiser allow-list, not a filter.
- The API takes either `doc` or `markdown` when writing a section and returns both. Run the OpenAPI drift script. Tell the assistant tools (COM-978) about the extended syntax in their description.
- The Word-template path keeps working from the derived Markdown until COM-995 retires it. `placeholder` stays for now, and new sections get a generated one.
- Migration test: raw SQL on a populated database (memories: migration-tests-orm-fixtures-drift, migrations-fresh-db-blindspot).
