Found on staging 2026-10-15 (Steve): leaver #68 for Abu Darby sat in *Executing*.

## What happened

The leaver started at 07:16:17. It signed Abu out, removed three groups, and then reached the Exchange step: his shared mailboxes and his send as / send on behalf rights on lists. At 07:16:23 the execution worker container was **OOMKilled** (exit 137, 512Mi limit). The run died with it, so the request was never finished. After 30 minutes the sweep marks a run like that *Failed* with Retry (COM-859). Retrying would hit the same limit at the same point.

## Why

- The execution consumer (two children, each with the whole app imported) idles at **~325Mi** of its 512Mi.
- Each Exchange step runs `pwsh` as a child process, in the same container. With only the ExchangeOnlineManagement module imported, before connecting, `pwsh` is already **204 MB** (measured in the staging container).
- 325 + 204 is over 512 before Connect-ExchangeOnline, or any cmdlet, has run. Exchange writes from requests worked yesterday only because the children happened to be smaller.
- The production preset (`size: production`) has the same 512Mi, so production is exposed too. The evaluation preset (384Mi) is worse.

## Fix

- Raise the execution container's limit in both presets, in `chart/values.yaml`, with the measured figures in the comment.
- Leave its request low, so the room is only taken while an Exchange step is running.
- Then Retry leaver #68 on staging: it carries on from where it stopped.

## Done when

- On staging, leaver #68 retried runs to *Executed*, or to the to-dos it should raise.
- The worker pod shows no new OOMKilled restart.
