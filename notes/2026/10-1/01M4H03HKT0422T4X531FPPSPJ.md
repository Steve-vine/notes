So that an Initiative exists as a first-class note type in the vault engine: a collection of Projects, the way a Project is a collection of Tasks. This is the Tauri-free core (`notuvia-core`) plus the decision record; the commands, MCP and UI follow in later tasks.

## Agreed work

- [ ] ADR: a new `initiative` Type following the ADR 0037/0047 checklist, and `initiative` as a new edge kind per ADR 0006 (not a reuse of `project`). Record the decisions below so they aren't a mystery later.
- [ ] `NoteType::Initiative` in `note.rs` (`as_str`, `from_value`), `initiative` added to `CANONICAL_KEY_ORDER` (29 → 30) and `is_managed_key`.
- [ ] `value("initiative", "Initiative", 6)` in `type_taxonomy()`.
- [ ] New built-in `initiative_status` taxonomy seeded in `seed_taxonomies()` with the same frame as `project_status` (backlog / todo / active / review / done, `done` terminal), scoped to `[Initiative]`, added to `BUILTIN_IDS` and `requires_done()`. Priority and Assignee scopes widen to include Initiative.
- [ ] Index (`index.rs`): `initiative` in `RESERVED`; an edge block writing `edges(src, dst, 'initiative')` plus the virtual `note_values` row, next to the `project` one; `initiative_status` in `known_filter_keys` and the `status:` expansion; a `child_projects(initiative_id)` query on `kind = 'initiative'`; `SCHEMA_VERSION` 12 → 13 with the history comment.
- [ ] Runtime (`runtime.rs`): `NoteView.initiative`; `list_initiatives()`; the `initiative` link set/cleared in `save_note` and `update_note_with_target`, valid on Projects only and validated on the backend that the target is an Initiative (projects don't check this today — don't copy that); `initiative_projects()`; `status_axis()` / `card_chips()` arms so `board(NoteType::Initiative)` works; `orphan_from_initiative` on delete, no cascade to projects.
- [ ] `ops.rs`: `initiative` on `CreateNote` and `NotePatch`. `set_project_sprints` stays project-only.
- [ ] `brief/data-model.md`: add Initiative to the Types table and fields-per-type; fix the stale "exactly one of memo|task|project" line (Schedule is missing too).
- [ ] Tests mirroring the project ones: Type options and scope matrix in `taxonomy.rs`, edge indexing and `status:` filter in `index.rs`, board grouping by `initiative_status`, save/link/list and delete-orphans in `runtime.rs`.

## Notes

Decisions baked in here (change the task if you disagree): initiatives have no identifier or numbering, no sprints or milestones, and are not part of the ADR 0027 family-taxonomy invariant — the initiative→project link is a plain parent edge. `fmt` and `clippy -D warnings` must be clean before merge (CI enforces both). Bumping `SCHEMA_VERSION` means the MCP sidecar must be rebuilt alongside the app or it'll fight the live index.
